# 前端工程内容标准（agentflow 通用底线）

> **定位**：与 `server-side.md` 配套的前端底线。agentflow 的 `design/fe` / `spec/fe` 已给骨架，本册补**组件 / 状态 / 表单 / 可访问性**的硬判据。
> **来源**：吸收 youc《前端工程规范》《前端与服务端命名目录迁移约定》《原型交互完备性约定》，并按 2026-11-02 登录批次的实测结论修正了防连点条款。项目有更强规范时以项目为准。
> **编号**：`FE-01…FE-09`，供 reviewer 在 finding 里直接引用（与 `server-side.md` 的 `BE-*`、`data-model.md` 的 `DB-*` 同一体系）。

## 0. 适用范围

`design/fe`、`spec/fe`、任何前端代码实现、前端代码评审、UI bug 修复。

## 1. 状态管理单一真源（FE-01）

**MUST**
- 表单 / 组件状态有**单一真源**，不出现「受控值」与「显示值」两套导致不同步（典型缺陷：开关未受控、清空后仍回显旧值）。
- 跨组件共享状态用明确机制（context / store / 提升 state），不靠 DOM 读值或全局变量偷偷传。
- 异步状态区分 `idle / loading / success / error`，不无限 loading 也不静默失败。

## 2. 表单提交与防重复（FE-02）

**MUST**
- 所有用户输入在**提交边界**做校验，错误信息就近展示、可访问（关联 `aria` / `role`）。
- **防连点用同步锁**：`useRef` 标志位、`submittingRef.current = true` 在事件处理入口同步置位。**异步 `setState` 的 `loading` 位挡不住同一轮事件里的双击**——`setState` 不同步，第二次点击读到的 `loading` 仍是 `false`，两个请求都会发出（2026-11-02 登录批次实测缺陷）。按钮 `disabled` 是**视觉与可访问性**手段，不是并发防护。
- 防抖 / 节流：搜索、发信、验证码等高频触发动作必须防抖或限频，明确防抖窗口（如「发送验证码 60s 冷却」）。防抖解决「连续触发」，同步锁解决「并发重复提交」，两者不能互相替代。

## 3. 错误与边界（FE-03）

**MUST**
- 全局错误边界捕获渲染异常，不白屏；关键路径失败有兜底 UI 与重试入口。
- 网络 / 业务错误区分展示，业务错误用服务端固定文案，不把堆栈 / 技术错误抛给用户。
- 加载态、空态、失败态齐备，不只有「正常态」。

## 4. 三方登录 / SSO 的 UI 边界（FE-04）

**MUST**（呼应 intake 范围维度）：若功能涉及三方登录（微信 / QQ / Google / GitHub 等），UI 必须明确：
- 三方入口的可见性与「未配置时的降级」（占位还是隐藏）；
- 回跳 / 回调页、深链、失败回退路径均有 UI 与状态；
- 与自有账号体系的账号绑定 / 解绑边界。

## 5. 请求生命周期（FE-05）

**MUST**
- 请求携带取消信号，或完成后校验请求身份：参数变化、卸载、身份切换后，**晚到响应不得覆盖新状态**。
- 监听 / 定时器 / 订阅 / Observer / 对象 URL 都有释放方；卸载后的回调不写状态。
- 缓存键含分页、排序、筛选与作用域（用户 / 租户 / 产品），请求参数与键用同一份规范化结果。

## 6. 契约字段与类型边界（FE-06）

**MUST**
- 字段按契约区分省略、`null`、空串、零值与空数组，**不用 `value || fallback` 吞掉有效零值**。
- 金额、点数与大整数保留既定单位与精度；时间区分时间点与自然日期及时区；未知枚举显式处理。
- 外部输入从 `unknown` 收敛并校验，不靠 `any`、非空断言或双重断言绕过契约。

## 7. 命名与目录（FE-07）

**SHOULD**：组件 / 文件 / 状态名表达意图，遵循项目既有约定；不造黑话缩写；不引入并行目录（`services` / `models` / `helpers`）或第二套 UI 框架。

## 8. 可访问性（FE-08）

**SHOULD**：交互元素可键盘操作、有可读标签、颜色对比达标；错误文案不只是颜色区分；弹层关闭后焦点合理恢复。

## 9. Reviewer 自检清单（FE-09）

- [ ] 表单 / 关键开关受控，无双真源（FE-01）
- [ ] **防连点用同步锁，不是只有 `loading` 位或 `disabled`**（FE-02）
- [ ] 高频动作有防抖窗口（FE-02）
- [ ] 加载 / 空 / 失败三态齐备，有错误边界（FE-03）
- [ ] 业务错误用固定文案，无技术堆栈外露（FE-03）
- [ ] 若有三方登录，回跳 / 降级 / 绑定边界已覆盖（FE-04）
- [ ] 晚到响应不覆盖新状态，监听 / 定时器有释放（FE-05）
- [ ] 契约字段的省略 / `null` / 零值区分处理（FE-06）
- [ ] 命名表达意图，无黑话、无并行框架（FE-07）

> finding 引用本册时写编号（如「违反 FE-02：防连点只用了 `disabled`」），不给只写文件名的 finding。
