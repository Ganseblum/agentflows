# Agentflow

用当前宿主的模型、认证、工具、权限、历史与原生 Agent 完成交付；不调用独立 Agentflow CLI、Provider、TUI、API key 或 MCP server。主任务负责范围、计划批准、协调、实际验证与最终决定。

## 四步主线

1. **查现状与定边界**：读取项目指令、真实代码、契约、当前差异与已有测试；说明用户结果、禁止事项、验收和停止条件。报告仓库状态先用 `git fetch`、`log`、`status` 校准。事实自己查，必要产品决定给推荐后询问，已有答案继续沿用。
2. **准备与批准**：按文档档位准备必要需求、设计、计划及环境。risky work 先由 Technical Director 界定边界；Plan architect 产出 `status: proposed` 计划后，由主任务显式批准为 `approved` 或退回，并写入计划变更记录。计划不是改码或远端操作授权。
3. **连续执行与验证**：按执行协议让行为测试先有效失败，再做最小实现与受影响回归；在有界简报内推进，真实阻塞按依赖分流。每次接受产物前对实际文件跑检查、核对基线以来真实写范围并回写计划状态与证据；不接受摘要代替输出。
4. **独立评审与交付**：作者不能批准自己的实现。重要改动和主任务亲写的改动都须独立评审，指定命令、原始 diff 与被审版本，真实走过主用户路径；要求修改时做一轮聚焦修复再审。最终将每条目标映射到可失败的检查，未验证的必需断言使结果为 `partial`，不能报完成。

在 Codex 使用原生子代理，一份简报只给一个角色；Claude Code、ZCode 仅在路由能降低风险时调用 `agentflow:<role>`。其他宿主无委派能力时顺序执行并如实说明。各写入者用独立分支或 worktree，写范围不重叠；评审与工具不因委派扩大权限。

## 首次接入（Init）

只在项目尚无接入约定时做一次；已有约定直接复用，只收集缺失或已变化的内容。

- 确认交付语言与读者、术语、分支纪律、真实检查命令、文档记录位置。目标仓已有体系就使用；否则按链契约选择普通仓或文档枢纽形态，不自创第三种目录。
- 将紧凑约定及检查入口写入目标仓 `AGENTS.md`，保留原有内容；使用当前任务已给授权，不重复确认已批准选择。跨仓宿主全局文件写入另按 hosts 协议取得明确授权。
- 接入约定必须写明：新批次建立当天检查文档；宣布完成前检查该仓全部适用批次；finding 必须修复或显式登记放行。跨仓命令为 `python3 <插件根>/tools/lab/doc_chain.py --root <目标仓根> <批次目录>`。
- 既有批次先跑基线，将真缺口与路径基准噪声分开；历史不回改。使用可计数、可打印原文的搜索，不用裸 `grep` 证明缺席，检查先打印命中再判断并排除否定或引用式误报。

Init 只写项目自身约定，不把本方法内部称呼搬进业务文档。插件角色来自宿主安装快照；改源码后要重建、重装并用 `validate.py installed` 检查漂移。未观察到宿主加载就不声称已生效。

## 任务分流

- 缺陷：按风险选调查 → 修复 → 独立评审 → 记录；已有复现的小缺陷可合并调查或记录，修复者仍不自批。用户可见缺陷留相同 Ego 操作序列的修前/修后证据，回归与状态联动遵守测试记录。
- 文档：用户明确要求整套文档或触及 risky 边界时走完整链；满足全部轻量判据的任务使用单文件 README。模板与阶段门以文档契约为准，轻量不豁免独立评审、实际验证或授权。
- 外部文档第二遍评审：冻结逐字快照和来源 revision，再按文档类型独立评审；记录引用须自包含，仓外文件用 `仓库@revision:路径`。目标系统缺口归 `provenance: external`，方法本应拦住的缺口归 `agentflow`；记录契约与桥流程见仓库 `reviews/README.md`（不在安装树）。
- 整体审核：按审核契约选覆盖范围，报告缺口与未知，不把文件计数或门通过当语义审核完成；审核材料只增不覆，来源版本与观察到的模型身份如实记录。
- 用户行为事件：沿 proposal 决策 → spec/fe 口径 → design/fe 字段契约贯通，验收在 QA；沿链工作的 design/fe 就是事件手册，不再造第二份。新增、复用、N/A 必须一致，按埋点契约评审。

## 判断词的可判定定义

先判 **risky work**：改公开或跨层契约、持久化、权限安全边界、共享流程时序/幂等，或难以回退时，必须先做架构判断并使用完整文档链。

未命中风险时，**小改动**还须同时满足单文件单层、不改契约或持久化、不触碰共享横切机制、已有已验证复现且实际检查通过；任一不满足视为 material。文档档位与角色数量由实际任务判断，小改动不豁免作者亲写改动的独立评审。

**相同原因**是同一检查/命令以同一规范化错误签名失败（去掉时间戳和绝对路径）。连续两次即停止重复尝试，重查假设、缩小范围或升级；没有新输入不得空转。改前基线同样失败只能说明不是本次新增回归，仍要分清既存缺陷、环境和夹具问题。

## 恢复与收口

中断后从既有计划和真实工作树重新推导每个包的状态；没有实际证据的包视为未开始。验收点在接受产物时回写，不拖到会话结束。未来的 `execution-coordinator` 当前不存在，持久队列、租约等职责不分配给虚构角色。

有独立评审的重要方法改动，结束前落 episode，保留每轮 `review_roundtrips`、负向结果和未验证项；格式复用 improve 环既有契约，目标仓不读写插件仓内部记录。方法没有疗效测量时使用 `measurement: none`，不声称已验证提效。

没有当前任务既有授权的提交、推送、合并、变基、拣选、部署、发布、远端删除或对外消息不执行；推送被拒时先 fetch/log/diff 只读汇报。详情以契约为准，不因连续执行或工具可用扩大授权。
