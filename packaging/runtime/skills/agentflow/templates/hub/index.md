# <项目名> 文档索引

> 本目录（`<project>-workflow-ai`）的唯一文档索引；新增、移动或删除文档必须同步维护本文件；相对链接带 `.md` 后缀。

## 从这里开始

| 场景 | 入口 |
| --- | --- |
| 开新需求 | `features/` 下建 `feature-<日期>-<主题>/`，按 proposal → spec → design → plan 推进；其 `README.md` 为唯一入口与进度板 |
| 修缺陷 / 登记事项 | `issues/README.md`（看板，四列：编号 / 一句话 / 记录链接 / 归属）＋ `issues/ISS-<YYYY-MM-DD>-<slug>.md`（记录本体，状态权威在它的 frontmatter）；只有被拒（`rejected`）条目移入 `issues/归档/<日期>/`，已验证记录原地保留 |
| 发版验收 | `releases/pending-test.md`（待验收）· `releases/todo.md`（待办与批次索引） |
| 查 feature 进展 | 各批次的 `README.md` 进度板（复选框附文档链接才推进） |

## 批次清单

按批次逐行登记，新增批次时在此追加一行（这也是「新开 feature」唯一要改的索引位）。
**本表不设状态列**——批次状态唯一权威在各批次 `plan/` 任务表，这里只写路径，不复制状态词。

| 批次 | 一句话范围 | 进度板 |
| --- | --- | --- |
| `features/feature-<日期>-<主题>/` | <做什么、不做什么> | `features/feature-<日期>-<主题>/README.md` |

> 没有批次时保留表头与一行占位，不要删表。批次完成并随瘦身批删除后，把该行移入
> `## 冻结历史` 记一行（git 历史可回溯），不在本表留状态词。

## 段落落点

每个批次的段落（proposal / spec / design / plan）由该批次 `README.md` 的**段落映射表**声明；
某段落落在本批次目录之外（例如另一个批次目录的 `docs/features/<批次>/`）时，在表里写明对方路径，不重复造册。
段落映射表声明了非空、非「—」落点的段落可缺目录，其余段落齐全。

## 维护纪律

- 新增、移动与删除文档必须同步维护本索引；
- 新增顶层目录或新的文档类型须先经用户确认；
- 相对链接带 `.md` 后缀。
