## Agentflow 全局规则（托管块，勿手改）

适用范围：本宿主的所有工作区。仓库级约定（检查命令、文档落点、分支前缀实例）由各仓 `AGENTS.md` 的「Agentflow 接入约定」节定义，不在这里重复。

### 1. 写操作前先确认分支

任何写操作之前——编辑文件、`git merge`、`git rebase`、`git commit`、`git push`、`git cherry-pick`——先运行 `git rev-parse --abbrev-ref HEAD` 确认当前分支。一次任务中切换过分支（合并、切分支排查、切换工作分支）后，后续每次写操作前重新确认。不得"先改后查"；发现已经先改后查，立即停下报告，不继续提交或推送。

### 2. 分支前缀与改动落点

仓库使用 `feature-*` / `release_sim_*` / `release_pre_*` / `release_prod_*` 前缀时：

- 允许：`feature-*` → `release_sim_*` / `release_pre_*` / `release_prod_*`；主干（`master` / `main`）→ `feature-*`。
- 禁止：任何 `release_*` → `feature-*`。
- 代码改动只落 `feature-*`。`release_*` 上只允许就地解决冲突，且不得借解冲突夹带其它改动；落在 `release_*` 上的其它写操作，先停下来向用户确认。
- 四类前缀之外的仓库按该仓自身规则执行。

### 3. 合并与推送是两次独立授权

解冲突不等于授权合并；合并不等于授权推送。未经当次明确要求，不执行 `git merge`、合并式 `git pull`、跨分支 `cherry-pick`、推送、发布或删除远端数据。推送被拒时先用只读的 `fetch` / `log` / `diff` 说清重叠面，由用户选择集成方式。

### 4. 证据

摘要不是验证；只有复现出来的确定性检查才算通过。无法复现或环境缺失的检查记为**未运行**，绝不计为通过。关于工具或宿主行为的断言，先做最小实验并保留退出码与逐字输出；做不到就标注为未验证。

### 5. 合并收口

- 手工解过冲突的合并按 **material 改动**对待：解决冲突就是在写代码，独立评审门适用；报完成前运行仓库的构建检查与**每个受影响单元的测试套件**，并留存原始输出。
- 测试失败不得用跳过 pretest、`--ignore-scripts`、只跑子集或缩小 glob 的方式换成绿色：要么修，要么把红作为阻塞升级给用户，并保留原始输出。
- 合并一个**曾被回滚**的分支时，先用 `git log --grep='This reverts commit' --oneline` 找到回滚提交，再用 `git show --name-status <revert>` 取文件清单逐项对账，逐文件确认合并结果。
- 评审 diff 必须包含源分支一侧：源分支还在时用 `source_branch..merge_result`；源分支已删除时用 `merge_result^2..merge_result`。只给 `merge_result^1..merge_result`（第一父提交基线）的评审看不见「源分支有、合并结果没有」的漏项。

### 6. 评审绑定 revision

独立评审针对确切的 `reviewed_revision`。revision 变化后重新开门，旧批准不得沿用到新提交；拿不到评审就如实记为未评审，不写成"已批准"。

### 7. 先问再假设（缺文档不猜、代码文档冲突先确认）

需求不清、契约不清、方向分叉，或简报/设计文档缺失时，**用提问交还决策，不得用未言明的假设推进**。事实去查（仓库、环境、平台文档），但决策以一行问题交给用户，最多三个选项并标出推荐项。

- **简报/设计缺关键要素，先反问，禁止用猜测补全。** 任务要求的简报、`design/` 目录、字段级契约或接口定义缺失或不完整时，立即停下用提问补齐范围、约束与验收，**不得**自行以"仓库既有模式""按推荐口径""以代码为准"等方式替用户补全设计空白再落地实现。缺少 `diff` / `HEAD SHA` / 测试原始输出时，如实记为未评审/未运行，不假装通过。
- **代码与文档冲突，先停一下确认，不默认"代码为准"。** 代码实现与现有文档、规格或用户描述不一致时，不得替用户拍板采信任一方；先摆出冲突点（哪份文档 / 哪段代码 / 哪个约束），由用户决定以谁为准再继续。唯一可默认代码为准的情形：用户已在本轮明确授权，或冲突纯属文档落后于已验收实现且用户已知。
- **开工前对齐隐藏约束。** 涉及计费、实时性、权限、合规、破坏性行为或跨系统副作用的任务，动手前先确认范围与边界（例如实时扣费 vs 跑完再报错、是否原路退款、哪些目录可改），不要等用户事后纠正。默认态度是"有歧疑就问"，而非"能猜就猜"。

### 8. 畏难而退的边界（扩大改动绕行 / 静默降级即缺陷）

遇到阻力时按既有协议升级或缩小边界，**不得用"超出能力/超出范围"作为跳过实质工作的借口**：

- **不臆造能力边界。** 没有证据不得声称"这超出我的能力/范围/职责"来回避本属任务内的工作；拿不准时先查（仓库、文档、工具清单），确属越权或跨边界的再停下向用户说明并交接，而不是替用户做"这事不该我做"的判定。
- **阻塞时走第一阻塞点协议，不扩大改动绕行。** 先列举已尝试的动作与已确立事实，继续不依赖缺失事实的那部分工作；只把需求 owner 必须选择的决策带推荐默认值交还；到这时才返回 `blocked`，并附所需的最小决策与解锁什么。看似合理的猜测不替代未答复的决策，也不为绕开阻塞而放宽改动。
- **不静默降级。** 达不到既定标准时不假装达标：检查失败就如实报红并升级，文档缺失就如实标缺，测试拿不到真实数据就标 `blocked`；不得用"建议人工/换工具/暂跳过"掩盖未完成的实质工作。

### 9. 可自纠报错：先执行纠正动作，禁止原样重试

工具报出的错误里有一类是可以**由自己纠正**的，默认动作是**立刻做那个纠正动作**，不是把同样的调用再发一遍：

- `File has not been read yet.` → 先 `Read` 该文件，再重试写入。
- `File has been modified since read`（文件在你读过之后被改过，常见于并发写入）→ 先重新 `Read` 拿到最新内容，再重试；不要拿旧内容反复硬改。
- `Found N matches ... replace_all is false`（`old_string` 不唯一）→ 补足上下文让它唯一，或明确用 `replace_all`；不要原样重发。
- `String to replace not found`（`old_string` 与当前文件不符）→ 重新读取核对原文，再构造替换串。
- `No changes to make: old_string and new_string are exactly the same`（空改）→ 说明这次改动本身无意义，停下确认意图，不要重发。

**判断依据：** 同一错误在 0–2 秒内以相同输入重复出现两次以上，就是原样重试风暴——立即停止重发，执行纠正动作，或按"相同原因连续两次失败"规则重新规划。重试不是进展，重试风暴在制造错误的进度假象。

### 10. 委派前核对子代理的工具清单与参数形态

子代理只能用它被授予的工具与参数。派活前先核对简报所需能力在它的工具清单内（例如只读评审角色没有 `Bash` 时，不要要求它跑命令或写文件），并确认工具调用参数符合该工具的必填形状：

- 出现 `Tool not found: <name>` 时，多数是子代理未获授权该工具——改派给具备该工具的角色，或由 Supervisor 在主对话执行，而不是反复重试。
- 出现 `Tool input failed inputSchema validation` 时，先按工具的必填字段与类型修正参数再调用；这类错误常成批出现在同一子代理上，属于参数形态或角色配置问题，不是偶发。
- 派发简报里点名需要的命令、文件写入、浏览器操作，必须与接收角色的工具清单一致；不一致就在派发前调整，而不是等它在运行时撞墙。

### 11. 检索与路径：先确认存在，再用对的工具

- **先确认路径存在，再 `Read` / `Grep` / `Glob`。** 拿不准时先用 `Glob` 或 `Read` 确认文件/目录真实存在，不要拿猜测的路径直接检索；路径写错产生的 `File does not exist` 是零信息量的失败。
- **优先用专用检索工具，而不是 shell 的 `grep` / `sed` / `cat`。** 专用工具带路径解析与结构化输出；shell 检索在中文关键词、`--include` 组合与 BSD grep 下会**静默漏报**——漏报比报错更危险，它会让"不存在"的错误结论看起来成立。
- **存在性结论必须可复核。** 用可计数、可打印命中文件与计数的脚本检索，先打印命中原文再判 PASS/FAIL；否定式表述与验收条目自身的引用式命中要排除——关键词命中不等于缺陷。
- **控制检索成本。** `Grep` 超时多发生在无边界的大范围递归；先用 `Glob` 缩小范围、带 `path` 或文件类型限定，避免对整个工作区做无界检索。正则里的中文/Unicode 字符类在部分实现下不合法，改用字面量或先验证正则可编译。
