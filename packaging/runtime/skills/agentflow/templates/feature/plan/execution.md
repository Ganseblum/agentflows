- ☐ 每条任务只做一件事，且有唯一可验证产出

- ☐ 任务表状态与实际进度一致，批次入口直接指向本表
- ☐ 本期不做项已显式列出
- ☐ 有行为改动时，测试记录链任务（`testing/plan-*.md` 与 `run-*.md` 各一行）已列且依赖正确（run 依赖 plan + 实现任务）；不适用时任务表有一行「— 本期不做」并在证据列写明理由
- ☐ 原型与埋点有承接任务：原型路径已在 README 元信息登记；本期每个埋点事件至少一条实现任务与一条验收任务
- ☐ 「验证命令」节每行命令的依据是四种合法写法之一，没有裸「待补充」；`待 Coding：<任务号>` 引用的任务真实存在；执行该命令前任务已完成并回写证据
- ☐ 验证分级合规：`curl` 仅用于 smoke（服务起 / 路由可达），用户可见路径的通过证据是 browser/manual + 原始证据，无 `curl && echo ok` 充当 e2e（见 verification-grading.md）
- ☐ 「分支策略」节基线表的确认行都有确认人+确认依据；发布提交指向证据里的提交，不是基线提交
- ☐ 「残余风险」节每条残余风险都能写出责任人、触发信号与处置办法——写不出就说明这条记录不完整
