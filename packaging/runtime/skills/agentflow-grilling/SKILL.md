# 压设计（Grilling）

**这是 Agentflow 主 skill 的执行细则的单点入口，不是第二份正文。** 方法契约只有一份，在
`../agentflow/references/grilling.md`（设计树与前沿、事实归属、收尾门、与决策记录的衔接）。
本文件只把触发条件与三个硬约束写清楚。

## 何时进这里

- 方案已成形，但担心漏了消费方、失败分支或不变量——**架构门之前**。
- 用户主动说「压一下这个设计」「看有没有没想到的」。
- 跨层 / 跨仓契约、认证会话、支付账本、权限、数据删除、部署顺序这类**难回退**的设计。

不适用：需求还没成形（先走 [agentflow-intake](../agentflow-intake/SKILL.md)）；纯执行任务；
已上线且不可回退（改做复盘）。

## 双触发：模板内嵌 + 本 skill

设计阶段有两条触发路径，**内容同源、职责不同**：

| 路径 | 何时生效 | 覆盖什么 |
| --- | --- | --- |
| **模板内嵌**（`design/be` §1.2.9、`design/fe` §1.2.9） | 每次写设计**自动**触发 | 保证「该压的时候不会忘」——固定核对表逐项填写，空着等于未做 |
| **本 skill**（用户显式要求） | 用户主动叫 | 交互式多轮：一轮只问前沿、每轮给推荐、按回答重算前沿 |

两条路径**不重复正文**：模板里的核对表引用的判据就是 `grilling.md`，本 skill 也不复述轮次格式。

## 三个硬约束

- **事实是 agent 的活，不是用户的**：文件、代码、配置、依赖版本自己查；跨文件/跨仓的事实派
  fresh-context 子 agent 去查，不拿父对话上下文猜。
- **决策是用户的**：每个决策摆到用户面前等回答，给推荐但**不替用户拍板**；没有推荐说明事实没查够。
- **一轮只问前沿**：依赖未定答案的问题留到下一轮；前沿为空才叫压完（每个分支都访问过、没有
  silently assumed）。

## 产出

三样：**已定决策**（含理由）、**未决问题**（含推荐与代价）、**还没覆盖的分支**。
用户确认「共同理解」之前，**不进入实现、不冻结设计**。未决问题进 `决策记录`；
难回退的决策落决策记录模板，grilling 只负责问出来。
