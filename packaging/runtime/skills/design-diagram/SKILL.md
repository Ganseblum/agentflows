# 设计图（design-diagram）

设计图不是自由创作，是**产出可被评审、可被机器检查、可被用例引用的证据**。一张图的价值不在好看，而在三件事：出了问题能在图上指到具体一跳、改了行为有东西会红、换个人看「怎么读」能独立复现你的结论。

本 skill 只负责**触发时机与执行顺序**，不重复各目标仓自己的图示规范。目标仓有规范时，条文以它为准，本 skill 管你怎么按顺序把事做完。

## 何时用

- 写或改设计方案，需要时序图、流程图、状态图、架构图、ER 图；
- 用户说「补齐时序图」「补状态流转」「图上没画失败分支」「图过时了」「图画得太乱」；
- 评审别人的设计文档，要判断图是否合格；
- 事故复盘后要补图——尤其是「为什么当时没人看出来」这类跨端链路。

## 何时不用

- 解释给别人看的一次性示意图（对话里画完即弃，不进仓库）；
- 纯数据图表（那是图表，不是设计图）；
- 已有彩图且口径未变，只是正文引用它；
- 只是列清单或字段表——那是表格，不是图。

## 三条铁律

| 编号 | 规则 | 为什么 |
| --- | --- | --- |
| DG-1 | **图只画主干，细节回文本。** 单图不超过 15 个节点；接口清单、字段表、错误码表不进图框，写进箭头标签或正文表格 | 见过 47 节点、2192 字的流程图，把方法表和错误码都画成了框：改一处要动整图，于是没人愿意改，图必然过时 |
| DG-2 | **每条关键箭头带稳定事件号**（`E01`…），状态节点带状态号（`S01_中文名`）；这些编号要被用例引用 | 图、状态表、用例共用一套编号，行为一改用例会红，图过时立刻暴露。只有图自己用的编号等于没有编号 |
| DG-3 | **同一件事只画一次。** 细节分支指向专册或专图，不在多张图重复 | 同一处越界流程在 3 张图各画一遍，改一处漏两处 |

## 四步执行（顺序不能换）

### 第 1 步 选层

判据只有一个：**这张图会不会被第二份文档引用？**

| 情况 | 落点 | 载体 |
| --- | --- | --- |
| 会（跨册总图：端到端链路、总架构） | 批次的 `design/diagrams/` | 可编辑源文件 + 可缩放导出 + 图清单 README |
| 不会（单册细节：状态机、判定顺序、ER） | `design/<册>/assets/`，按「册号-图名」命名 | 同上 |
| 需要随文评审、要能 diff | 设计正文 | mermaid 代码块 |

选完记住一条：**同一主题只能活一处**。升级成彩图后，删掉正文里同主题的 mermaid 简图——两处并存必然漂移，评审时没人知道该以谁为准。

**涉及新表或改表必须出 ER 图**：只画表、主键、外键与关系，索引、字符集、默认值进正文表格；每条关系标 `1:1 / 1:N / M:N`，多对多必须画出中间表；只画本次新增或改动的表，既有表灰底标「既有」。

### 第 2 步 画

- mermaid 用模板：[时序图](templates/sequence.md)、[状态图](templates/state.md)、[ER 图](templates/er.md)。模板里的无障碍描述与主题块**要一起抄**，它们通常是门禁项，不是可选装饰。
- 配色表达**角色**而不是审美：本机/客户端、云端服务、外部依赖、安全边界、判定与编排、失败分支、存储各一色，同色不得表示两种角色；图内自带图例。
- 三条硬约束，违反其一即不合格：
  1. 单图不超过 **15 个节点**，接口清单与错误码**不画框**；
  2. 时序图开 `autonumber`，每条关键箭头带事件号；状态节点写 `S01_中文名`；
  3. **失败分支必须画出来**（`alt/else`、`opt`、`loop`），只画 happy path 等于没画。
- 每条箭头都要有描述意图的标签，且不能只有事件号：`E07` 不合格，`E07 校验失败返回 400` 合格。单条标签控制在 60 字内，超了换行或把细节移进正文。
- 布局守住四条：**节点不重叠、连线不穿无关节点、标签不压线、内容不出画布**。交叉控制在「边数 × 0.3」以内，回边统一走同一侧，平行线间距至少 8；主线纵向、失败支放左列、成功支放右列，不要斜穿。
- 每个 mermaid 块**紧跟一段「怎么读：」**，点名「哪几条分支要能独立观察」「哪两跳不能颠倒」。写「本图展示了 X 流程」等于没写。
- 用生成器出彩图时，**布局定义文件是唯一真源**，不要手改产物——手工维护两份必然漂移。

### 第 3 步 验

先跑目标仓自己的图门禁（有的话），视图示规范里的命令。跑门禁时注意两件事：

- **只查本批改动，别全仓裸跑严格模式。** 严格模式加全量会把历史存量一次性升级成错误，输出淹掉本批真正的问题。
- 分清「能改的」和「改不了级的」：有些提示是脚本硬编码的软提醒，严格模式也不会让它变红，得人工判断接不接受。

判据是**错误数为 0**。另外这几项脚本查不了，必须自查：

- 状态图有没有**九列明细表**，且「失败、重试、恢复」列与异常矩阵一致；
- 图里的口径与当前代码是否一致——不一致时以代码为准改图，**不要改代码去迎合图**；
- 失败与成功分支不能只靠红绿区分（红绿色盲约 8%），要同时用文字或线型区分。

### 第 4 步 登记与回链

1. **跨册总图**登记进该目录的图清单：文件、图名与范围、对应文档与小节、依据（决策号或 Issue 编号）；
2. **单册图**不进总图清单，把图号与范围写在该册正文和批次入口的图清单段；
3. 正文写「图名（范围，长描述见下文「怎么读」）」的图片引用 + 源文件链接 + 「怎么读」；图号登记进清单，正文按图号引用而不是按文件名，这样重命名文件不用改正文；
4. 图例写清颜色、形状、线型、尺寸四维；尺寸若只是排版结果，要明说「不代表重要性或容量」；
5. 事件号回链到用例：「覆盖 E09–E11」写在测试计划或端到端脚本里，让图过时能被测试红暴露。**引用了就要真写断言**——只在注释里提一句事件号，等于没接上。

## 反例（都真实发生过）

| 反例 | 后果 | 正确做法 |
| --- | --- | --- |
| 把方法表、错误码表都画成框 | 改一处要动整图，没人愿意改，图必然过时 | 主干十几个节点，清单回正文表格 |
| 同一处越界流程在多张图各画一遍 | 改一处漏两处 | 只留一个出口，其余写「见某图」 |
| 只写「点了登录没反应」，不画授权校验的失败分支 | 真缺陷在图上完全不可见，于是没人去验 | 每个静默失败点单独一条分支，并配用例 |
| 图里有彩图、正文又留 mermaid 简图 | 两处漂移，评审不知以谁为准 | 删简图，正文只留引用 |
| 图有事件号但没人引用 | 不知道图什么时候过期 | 至少一条用例断言同一组事件号 |

## 交付前自检

**先跑门禁，再逐条过人工项**——门禁全绿不代表图合格。

门禁项（能机器判）：

- [ ] 目标仓图门禁错误数为 0（只查本批改动）
- [ ] 时序图开了 `autonumber`；事件号连续、不重复
- [ ] 每块 mermaid 都有无障碍标题与描述（`accTitle` / `accDescr`，最容易漏的一项）
- [ ] 每块图后有「怎么读」，且点名了分支
- [ ] 状态图节点写全名 `S01_中文名`，任何引用处都不简写
- [ ] 每条箭头有意图标签，且不只事件号；单箭头不超过 60 字
- [ ] 单图不超过 15 节点
- [ ] 彩图已登记清单，且同名导出文件至少一份存在
- [ ] 彩图无节点重叠、无内容出画布
- [ ] 无真实内网地址、凭据、用户数据（见下方已知误报）

人工项（脚本查不了）：

- [ ] 选层正确，且没有同主题重复
- [ ] 状态图有九列明细表，每个状态都有一行（不只是图里出现过的那几行）
- [ ] 失败分支齐全，静默失败点能单独观察
- [ ] 图有**标题 + 范围**：一句话说明这张图回答什么问题，并写清覆盖什么、不覆盖什么
- [ ] 失败与成功分支不只靠红绿区分
- [ ] 图例四维齐全；尺寸不隐含未声明语义
- [ ] 图号已登记，正文按图号引用
- [ ] 图数在上限内：单个批次的跨册总图不超过 6 张、单册细节图不超过 8 张
- [ ] 事件号已回链到至少一条用例，且那条用例真有断言

## 出错时查这里

看到门禁报错但不知道怎么改，翻[门禁报错对照](references/gate-findings.md)：
报错原文 → 原因 → 改法三段对照，含已知误报，以及「哪些地方门禁根本不管」的覆盖表——
后者决定你还要手工检查什么，**别把门禁绿当成图合法**。

## 与其它能力的分工

- **要哪些图**由文档交付链定义（设计需含失败分支时序图、ER 图或状态图等形态要求）；本 skill 只定**画成什么样算合格**，不新增图种，也不改形态判据。
- 设计压测判断方案有没有漏洞，本 skill 判断图画得够不够格做证据；两者可同批进行，但不要拿一张好图代替压测结论。
- 独立评审加载本 skill 时，重点看图与代码口径是否一致、以及「怎么读」是否真的能被第三人复现。
