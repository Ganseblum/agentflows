# 开工提问（Intake）

**这是 Agentflow 主 skill 的执行细则的单点入口，不是第二份正文。** 方法契约只有一份，在
`../agentflow/references/intake.md`（六要素、红线、提问预算、任务简报形态、路由）。本文件只做两件事：
把触发条件写清楚，让用户在「需求还没成形」时能直接叫到这里。

## 何时进这里

- 用户给了一段模糊想法，没说清目标 / 交付物 / 验收 / 上下文 / 分工 / 节奏。
- 用户要"先别动手，我们理一下要做啥"。
- 准备委派但简报缺关键要素——缺要素就先在这里补齐，**不是让 worker 自己猜**。

不适用：需求已经很具体、单步就能做完的小事；纯执行任务。

## 读什么

1. 先读 [`../agentflow/references/intake.md`](../agentflow/references/intake.md) 的**起步先判状态**、
   **六要素**、**提问预算**与**依据缺失时**：先判小事 / 已完整 / 混沌 / 其余四档，混沌时按「最近 3 轮」
   先猜 2～3 个让用户挑；一次最多 2 个问题（每题最多 3 选项并标推荐）、能假设就假设但要列出来；
   依据缺失（简报 / design 目录 / 字段级契约 / diff / 测试原始输出）时停下问，不替用户补空白。
2. 进入某类功能时，读 [`../agentflow/references/intake-scope-dimensions.md`](../agentflow/references/intake-scope-dimensions.md)
   的对应领域表，**主动逐维确认**（这一张勾选表不计入上面的 2 问预算）——领域清单治「范围想全」，
   2 问纪律治「不打断」。
3. 判断词与门的关系（什么算 material / risky）在 [`../agentflow/SKILL.md`](../agentflow/SKILL.md) 的
   「判断词的可判定定义」节。

## 硬约束（违反即缺陷）

> **本节是入口处的提醒，不是条款正文。** 每条约束的正文与判据都在
> [`../agentflow/references/intake.md`](../agentflow/references/intake.md)；两处表述不一致时**以正文为准**，
> 并把本节的措辞改齐（不要让提醒变成第二份真相）。

- **红线原样保留**（正文：§六要素）——用户说「不要动 X」就写「不要动 X」，不改写成「谨慎处理 X」；
  碰生产 / 删数据 / 权限 / 计费而原话没写红线时，问一句「哪些不能动？」
- **验收写证据层级**（正文：§六要素）——用户可见入口只接受 `browser` / `manual`；`api` 200 不能证明页面可用。
- **缺依据先问，不替用户补空白**（正文：§依据缺失时）——简报 / design 目录 / 字段级契约缺失时停下补齐，
  不得用「按仓库既有模式」「按推荐口径」补全；缺 `diff` / 测试原始输出时如实记未评审 / 未运行，
  结论上限 `partial`。
- **代码与文档冲突先确认**（正文：§依据缺失时）——先摆冲突点（哪份文档 / 哪段代码 / 哪个约束），
  由用户定以谁为准；不默认「代码为准」，除非用户本轮已授权，或纯属文档落后于已验收实现且用户已知。
- **不把假设写成已拍板**（正文：§提问预算）——推断列成「我按这些做」，用户确认后才进决策记录。
- **点名的对象不在不顶替**（正文：§点名对象不在时）——任务对象（路径、文件、报告）查不到就进「要你定」
  让用户给，不拿相似文件顶替；辅助材料不在写成假设即可，不打断。
- **预判改写成待办**（正文：§输出）——原话里的「应该不需要了」写进简报时改成「先验证……」。

## 产出

按 `intake.md` 的「输出：任务简报」形态给一份简报（目标 / 交付物 / 验收 / 上下文 / 红线 / 分工 / 节奏），
对象没定的位置写 `<待定：…>`，不编。需要用户拍板且未关闭的条目挂到 `决策记录` 编号，
不另起第二份待决清单。
