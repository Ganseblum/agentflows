# 宿主接入（Host Init）

> 本文只解决一件事：让**跨仓库**的 Agentflow 纪律在每个会话默认在场。
> 插件安装、仓库接入是另外两件事，别混在一起。本文是 Host Init 协议的**唯一权威**；
> [templates/host/README.md](../templates/host/README.md) 只是操作清单，冲突时以本文为准。

## 三层分工

| 层 | 解决什么 | 载体 | 何时生效 |
| --- | --- | --- | --- |
| 插件安装 | 角色、工作流、模板 | 宿主插件缓存（如 `~/.zcode/cli/plugins/cache/...`；源面的 `.zcode-plugin/`、`.codex-plugin/`、`.claude-plugin/`、`.qoder-plugin/` 是 manifest 目录，不是缓存） | 宿主加载插件时 |
| **宿主接入（Host Init）** | **跨仓纪律：写前查分支、合并与推送授权、证据纪律、合并收口、评审绑定 revision** | 宿主自己的全局指令文件 | 该宿主的每个会话 |
| 仓库接入（Init） | 该仓的具体约定：检查命令、文档落点、工程基线入口、分支前缀实例 | 目标仓 `AGENTS.md` 的「Agentflow 接入约定」节（骨架：[templates/hub/repo-rules.md](../templates/hub/repo-rules.md)） | 在该仓工作时 |

为什么需要中间这层：仓库接入只在该仓被打开时加载，换一个仓就没有了；插件只在该技能被调用时加载。分支纪律与证据纪律必须在**任何仓、任何会话**默认在场，否则一个没有加载到规则的会话会在 release 分支上直接改代码——2026-10-23 的一次 Codex 合并会话就是这样发生的：插件与 SKILL 都在，但分支规则只存在于另一台宿主的用户级文件里。

## 全局层写什么、不写什么

**写**（跨仓不变，且能写成可执行条款）：

- 任何写操作前先确认分支；一次任务中切换过分支后重新确认，不靠会话记忆。
- 仓库使用 `feature-*` / `release_sim_*` / `release_pre_*` / `release_prod_*` 前缀时的合并方向与改动落点。
- 合并与推送是两次独立授权；解冲突不等于授权合并。
- 摘要不是验证；无法复现的检查记为未运行。
- 合并收口：构建 + 每个受影响单元的测试；测试红不得用跳过换绿；回滚过的分支先对账。
- 评审按 `reviewed_revision` 绑定，revision 变化重新开门。

**不写**（属于仓库接入，写进全局会换仓即错）：

- 具体检查命令（`go test ./...`、`tsc --noEmit` 之类）。
- 文档与记录落点、批次目录形态。
- 某一台机器上的绝对路径、某个仓的分支名实例。

## 托管块协议

写入宿主全局指令文件时，只写一个带标记的块；块外内容一字不动。

```markdown
<!-- agentflow:begin vX.Y.Z -->
（规则正文，来自 templates/host/global-rules.md）
<!-- agentflow:end -->
```

示例里的 `vX.Y.Z` 是占位符，不是当前版本；实际写入时替换为当前插件版本。

1. **默认 dry-run。** 先打印目标文件的 `realpath`（解析符号链接后的真实文件）、将写入的完整块、以及块外是否会变动。目标若是 symlink，必须把真实落点单独列出并等用户确认。用户确认后才写。
2. **只改块内。** 文件已有内容但**没有托管块**时，追加在末尾；追加前检查文件末字节，不是换行就先补一个换行——这是**唯一允许的块外改动**，必须在 dry-run 里显式列出。除此之外绝不重排、重写或删除块外内容。
3. **任何会改变文件内容的写入之前都先备份。** 包括首次追加和后续版本替换；备份名 `<文件名>.agentflow-backup-<YYYYMMDD-HHMMSS>`，报告里给出路径。备份必须落在 `realpath` 旁且是普通文件（用 `cp -L` 之类解引用 symlink），不能用保留符号链接的复制方式——否则备份与被改文件是同一份。版本替换不是"没有风险"的写操作。
4. **幂等。** 块存在且版本相同则不写；版本不同只替换块；标记不完整（只有 begin 或只有 end）时拒绝写入并报告，不猜。
5. **不自动写。** 技能加载、会话开始都不触发 Host Init。写 home 目录是跨项目写操作，与合并、推送同级，需要当次明确确认。
6. **写完要做三项校验，并保留原始输出。** 只让宿主复述首行不够——它只证明块开头在。
   - 块外内容与备份一致：分别删掉两个文件的块后 `diff`，必须为空；dry-run 声明过的「补末尾换行」是唯一例外，比较前在备份侧补上同一个换行。
   - 块内容与模板一致：把模板中的 `{{version}}` 替换为当前版本后，与文件中的块 `diff`，必须为空。
   - 宿主确实加载了它：在新会话里要求宿主逐字复述块内第一行 `## Agentflow 全局规则（托管块，勿手改）`。拿不到复述就记 `blocked`，不算接入完成。
7. **宿主拒绝写工作区外文件时不要硬试。** Claude Code 把文件访问限制在 cwd 内（`docs/host-platform-facts.md` C8），Codex 默认 `workspace-write` 沙箱（X1）。宿主拒绝时，把完整块打印给用户，由用户自行粘贴；粘贴后仍做第 6 条三项校验——前两项由用户运行并把原始输出带回（块外内容与备份一致、块内容与模板一致），第三项由用户在新会话复述首行；三项都拿到才算完成。
8. **验证记录落在插件仓。** 在插件仓会话里工作时，把观察结果写进 `docs/host-platform-facts.md` 对应行；在目标仓会话里工作时，不写插件仓的记录——把宿主的逐字回复留在会话里，交给插件仓一侧落盘。交接完成前，该宿主行保持"未验证"。

## 写前摘要与托管工具

已有全局写入授权后，可用插件的 `workflow.py managed-preview` / `managed-apply` 将预览绑定到实际单文件内容。目标使用已核实的真实路径，准备替换版本占位后的块内正文，传入成对 begin/end 标记；无标记模式表示整文件托管，不用于覆盖有其他指令的全局文件。

```sh
python3 <插件根>/skills/agentflow/scripts/workflow.py managed-preview --target <真实目标文件> --content <块内正文文件> --output <新预览.json> --begin-marker '<实际begin标记>' --end-marker '<实际end标记>'
python3 <插件根>/skills/agentflow/scripts/workflow.py managed-apply --preview <预览.json> --fingerprint <预览指纹>
```

预览绑定目标存在性、原内容及执行位、拟写内容与标记；应用前重检，手改、摘要不符或标记异常就拒绝旧预览，重新核实，不手工伪造摘要。成功应用仍执行上文备份、块外比对、块内比对及新会话加载验证；工具输出不能替代宿主加载证据。

begin 标记含版本号时，用 `--begin-marker` 指定文件中的旧标记，另用 `--new-begin-marker` 指定本次新版本标记；块内正文不包含标记。这样版本行和正文一并进入预览摘要，不能只更新正文而留下旧版本号。字段见[工具用法](workflow-tool.md#托管单文件)。

该工具不授予 home 写入权限，不自动安装或升级插件。它只执行单文件协议；摘要重检不等于对恶意并发写入者的原子隔离，也不承诺跨文件事务。失败时报告实际状态和备份，不盲目恢复以覆盖用户随后修改。

## 版本与漂移

- 托管块头的版本号必须等于当前插件版本（manifest 的 `version`）。插件升级后，Host Init 需要重跑一次；版本不同就是漂移。
- **改模板必须同时 bump 插件版本。** 只改 [global-rules.md](../templates/host/global-rules.md) 而不 bump 时，按规则 4「版本相同不写」，重跑 Host Init 是 no-op，宿主里会留下旧副本——这正是"模板改了、宿主里旧副本没人发现"的路径，必须避免。
- README 的升级步骤（重建生成树、刷新 marketplace、重装）里应同时包含"用过 Host Init 的宿主重跑一次"。
- `validate.py installed` 只比对**插件快照**，不检查宿主全局指令文件。本仓尚未提供 `validate.py host_init`：`tools/lab/validate.py` 在受保护面内，新增门项属于门变更，需单独人工评审。在那之前，托管块的版本行、第 6 条的三项校验输出、以及 `docs/host-platform-facts.md` 的记录就是审计线索。
- 不要手工编辑托管块。要改规则，改 [templates/host/global-rules.md](../templates/host/global-rules.md) 并 bump 版本，再重跑 Host Init——否则宿主里的副本会和模板分叉，且没有东西会发现。
