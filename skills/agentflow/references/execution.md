# 执行与验证

本文是测试先行、环境准备、选测、证据复用、阻塞分流和执行证据的唯一方法定义。角色只规定分工；记录形态见[测试记录](test-records.md)，权限与独立性见[委派契约](contracts.md)。

## 先界定本次行为

实现前读取实际规则、代码、契约和测试，确认用户结果、非目标、禁止事项、失败与恢复；优先复用已有能力。预期来自已确认的需求或契约，不能从当前实现、真实响应或被测算法反推答案。只询问仍缺失且会改变行为、权限、兼容性或验收的决定；已答复内容继续沿用。必要选择未答时仅暂停依赖它的工作，预选、空答案、超时和工具返回已接受都不是答复。

按[文档档位](document-chain.md#文档档位)选择材料，执行期间继续使用同一需求与状态来源。任务已有授权、参数齐全时，必要预览之后直接继续，不反复问“是否继续”；明确规定的人工门、宿主权限和范围约束仍然适用。

## 测试先行的适用范围

| 改动 | 顺序 |
| --- | --- |
| 新增功能、缺陷修复、改变可观察行为的配置或脚本 | 目标测试有效失败 → 最小实现 → 目标与受影响回归通过 → 必要重构后再验证 |
| 行为不变的重构 | 先确认现有相关测试通过，重构后重跑受影响回归，不故意制造失败 |
| 纯文档、分析、规划、评审、无可执行行为的静态资产或类型声明 | 核对内容、引用、格式和适用检查，不机械新增行为测试 |

按一个可验收的用户行为纵向完成小循环，不先批量编造依赖未知内部结构的测试再一次实现。已有测试确实表达目标时可以复用；预期不得迁就实现，不以内部调用次数替代用户结果。

## 有效失败与实现

写生产实现之前运行目标用例，记录命令、精确用例名、预期失败、实际失败和退出状态。失败必须触达目标路径，并能说明是尚未实现或错误的目标行为；未发现测试、损坏夹具、依赖缺失、断言自身错误和工具崩溃均不是有效目标失败。

有效失败成立后写最小通用实现，运行相同目标用例及受影响回归。不得删测试、弱化断言、使用 `only`、跳过必需检查、硬编码特定测试输入或 mock 被测实现制造绿色。重构仅在目标和相关回归保持通过时进行，破坏通过状态就修复或撤回该次重构。

## 环境预检与选测

开工前实际核对项目目录、依赖、启动入口、测试 runner、所需账号角色、测试数据和权限。用既有命令运行最小健康检查；命令的出处和服务地址沿用计划中的验证与启服清单，不猜端口或健康路由。环境缺口应在依赖实现开始前显式出现。

测试范围依据验收、最终 diff、调用方和共享机制确定。默认运行目标用例与受影响回归；共享底层影响广、范围无法可靠界定、跨模块回归或项目 CI/发布要求时扩大范围。筛选必须保留原入口的初始化、fixture、环境和清理；报告未发现目标用例不算通过。

证据仅在相关代码、测试、依赖、配置与环境都未变化，且对应本次验收时复用；任一变化或新疑点使相关证据过期。记录选测依据、未覆盖范围和复用来源，不为重复流程重跑无变化检查，也不因耗时省略必需验证。**本仓 `validate.py all`、目标项目明确要求的全量检查和必需 CI 不因选测或证据复用被裁掉。**

## 执行路线与数据

- 浏览器自动化先用 Ego Light（`ego-browser`），执行前运行 `ego-browser skill`。原始脚本与截图、DOM、网络证据按目标仓现有位置保存。不新建平行 Playwright 套件；项目已有 runner 时运行既有套件。
- API 与服务测试使用项目原生命令或客户端，核对协议、业务结果和副作用；无副作用时写显式反向断言。
- Ego Light 不能覆盖的宿主登录态或本机交互，由主任务按测试执行者编译的步骤执行，回传原始证据再判结果。该路线只补覆盖缺口。
- 数据真实优先：能从真实接口或环境获取的一律使用真实数据；只有真实拿不到的环节才逐项声明 Mock 对象、原因和受影响用例，禁止全链路 Mock 冒充端到端。计划未声明 Mock 而依赖不可达时标阻塞，不静默替换。
- 凭据只记录运行时注入方式，不落到计划、脚本、日志、截图或报告。夹具只证明受控场景，不能代替真实服务、权限、协议或操作系统能力。

## 阻塞与连续推进

| 观察到的阻塞 | 动作 |
| --- | --- |
| 共享构建或共同环境预检失败 | 停止全部依赖任务，不在坏构建上跑全集 |
| 独立模块或局部任务失败 | 保留失败与依赖关系，只阻塞依赖它的任务；其余已授权工作继续 |
| 可在已授权测试基础设施范围恢复 | 建立或修复 runner、fixture、本地服务，再验证；不擅改生产实现 |
| 缺少产品决定、权限、真实账号或生产修复授权 | 列已查事实、建议与最小所需输入，继续无依赖部分 |
| 计划指纹失效、越界、不可逆危险操作 | 停止相关写入并重新定位，不隐式扩大授权 |

同一规范化原因连续两次失败就停止重复尝试，带新假设重规划；不能在不变输入上空转。部分失败不是提前结束所有工作的理由，也不是放宽 smoke、权限或完成条件的理由。详细结果分类仍由[契约](contracts.md#worker-结果)定义。

## 执行证据工具

插件内便携入口为 `scripts/workflow.py`，仅用 Python 标准库。它不启动模型、不批准计划、不更新任务或缺陷状态，也不提供沙箱。输入 JSON 是既有 Markdown 计划与测试记录的执行说明，输出 JSON 和原始日志是它们引用的证据，不是第二套进度系统。

```sh
python3 <插件根>/skills/agentflow/scripts/workflow.py seal --root <项目根> --input <request.json> --output <sealed.json>
python3 <插件根>/skills/agentflow/scripts/workflow.py verify --root <项目根> --sealed <sealed.json> --fingerprint <指纹>
python3 <插件根>/skills/agentflow/scripts/workflow.py run --root <项目根> --sealed <sealed.json> --fingerprint <指纹> --output <新证据目录> --phase green
python3 <插件根>/skills/agentflow/scripts/workflow.py inventory --root <项目根> --input <mapping.json>
```

执行说明声明项目内计划、精确 `allowed_writes`、任务依赖、`argv` 数组、工作目录、超时、任务类型、reporter 与具名用例。测试任务必须声明精确报告名；`exit` 只用于预检，不能冒充行为测试。TAP、JUnit、Go JSON、Jest JSON 的用例名必须唯一并准确对应；空报告、缺用例、重复歧义、跳过/todo、损坏或未完整结束的报告不算通过。JUnit 文件须由本次命令生成，不能使用旧报告。

完整输入字段、报告命名、托管命令和可复制模板见[证据工具用法](workflow-tool.md)。该文档只定义工具接口；执行方法仍以本文为准。

授权基线与最终执行快照分开：范围内实现可以改变允许路径，计划本身仍被冻结；越界或 HEAD 漂移须重新封存。`run` 在执行前绑定最终内容，并检查执行期间输入是否改变，防止旧证据冒充当前结果。`--phase red` 只记录准确目标用例失败与命令非零，失败因果仍需对照需求复核，不能只凭 runner 失败认定有效失败。

退出 0 仅表示当前操作满足约定；1 为命令或断言失败，2 为非法输入，3 为漂移/越界等拒绝，4 为部分阻塞。任务结果沿用 `pass/fail/blocked/not-run`，执行满足预期时覆盖状态仍是 `needs_review`。原始 stdout/stderr 保存在新证据目录，不覆盖旧轮次，也不只保留哈希；持久化前按记录规则处理敏感内容。

## 遗留补测

复用测试设计者与执行者，不新设角色。先盘点 Git 可见文件和功能，明确生产、测试、基础设施、排除理由；每个生产文件有功能归属，每个功能有真实入口、验收来源和具体测试。用例说明单元、集成和 E2E 的适用性，缺 runner/环境不等于不适用；计划测试可以尚未创建，但路径与候选范围必须明确。

按风险、依赖与执行预算分批，精确计划绑定本批允许写路径和命令。补测授权仅覆盖声明的测试、fixture 与基础设施，不吞并生产修复。需要生产变更时隔离该候选、提出最小范围并继续其余工作。`inventory` 只核对声明的结构与引用，不能证明功能、分支和断言穷尽。

## 三种结论分开

1. **记录合法**：字段、引用和计划关系通过确定性检查。
2. **执行满足预期**：本次快照的指定用例真实执行，原始报告和结果可复核。
3. **覆盖经过复核**：独立评审从真实入口、需求与失败路径反查测试，检查断言是否有效，记录遗漏与处置。

前一项不自动证明后一项。测试全绿仍可能遗漏关键场景；自查不冒充独立评审。最终按验收点回写既有任务状态与证据，声明失败、未验证、外部阻塞和剩余动作；未完成的必需验证不能报完成。宿主加载、远端 CI、合并、发布与部署各自需要实际证据。
