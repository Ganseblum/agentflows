# 文档交付链（链契约）

当用户要求为某 feature **产出**文档集（需求提案 / 规格 / 技术方案 / 实施计划）、某 feature 先有文档尚无代码、**或在目标仓实施一个新 feature（代码工作随行）**时，走这条链：

```
接入（Init）→ 采集访谈 → 提案 → spec → 设计 → 计划 → 实施
```

每阶段有必需骨架（见 [`templates/feature/`](../templates/feature/README.md)），质量以「阶段产出是否齐全、可核验」为准，而不是以某条机器判据为准。

## 文档档位

本节是材料分档的唯一判据，角色、生成器与入口文档只引用它。先遵守用户要求的交付物与写入权限，再按风险选档；材料档位不授予新目录、代码、全局文件或发布权限。

- **琐碎静态改动**：无可执行行为变化的文字、引用或静态内容小改，核对实际内容、路径与适用静态检查即可，不机械建 feature 材料或独立评审记录。涉及方法契约或高风险决定时仍须按其风险升级。
- **轻量（light）**：用户未要求完整材料，且下列六项全部有依据为「是」时，使用唯一的 feature `README.md`，按[轻量模板](../templates/feature/lightweight.md)内嵌需求、任务、最小用例、运行证据与独立评审结果；不额外强制 proposal、design 或测试 plan 文件。
- **完整（full）**：六项任一为「否」或「未知」，或用户明确要求完整材料，走下文全阶段。纯后端也可能需要 full；小 UI 在满足六项时可以 light。已有项目材料可按章节映射复用，不复制第二份正文。

| 轻量条件 | 要证明什么 |
| --- | --- |
| 目标与行为已确认 | 范围、失败行为与验收来源已定，无待裁决的产品分歧 |
| 无跨层或公开契约变更 | 单层改动，不改变跨层/跨仓接口、公开 schema、CLI 或记录格式 |
| 无持久化或权限变更 | 不改变持久化、数据模型、安全、认证或授权边界 |
| 无共享时序或不可逆变更 | 不改共享横切机制、时序、幂等或难回退副作用 |
| 单一部署单元且回退明确 | 影响范围有界，恢复动作与回验入口明确 |
| 验收可执行 | 有真实测试入口或明确人工步骤，所需账号、数据与权限可用 |

light 的单层低风险行为改动仍须真实验证与独立评审，作者是 Supervisor 或 worker 不改变要求；自检不等于独审，独审也不等于用户批准。独审不可用时按[评审能力分级](contracts.md#评审能力分级)如实记 `partial`，恢复后补审。证据可以内嵌在已授权的 README 中；未获持久写入授权时交回会话并说明缺口，不另立记录根。范围扩大时先重新判档并补足所需材料。

立项生成使用 `new_feature.py --tier light|full`：light 仅生成 README，不接收 tracks/prototype；full 必须显式给非空 `--tracks be,fe,qa,ui` 的所需子集，QA 为必要公共轨（遗漏时生成器补入），`--prototype` 为可选布尔开关。full 生成公共 README、proposal、plan、spec checklist 与选中轨道，不预建 testing 占位文件；`--template-dir` 也按同一选择规则取模板，不整树盲拷。生成器只回填元信息与段落映射，不替代风险判断或完成材料。

## 各阶段必需骨架

本表用于 full；light 的同义内容集中在唯一 README。下表路径相对于接入时确认的功能目录。目标仓有自用模板或目录时，在已有入口标出本表各阶段的对应章节、链接和证据位置，沿用其载体。QA 验收必备，BE/FE/UI 按影响范围选轨，未选轨在入口写 N/A 与理由。

| 阶段 | 位置 | 必需骨架 |
| --- | --- | --- |
| 接入 | Init | 目标仓接入节（[templates/hub/repo-rules.md](../templates/hub/repo-rules.md)）：硬判据 + 仓事实槽位 + begin/end 标记 |
| 提案 | `proposal/proposal.md` | 目标承接表、范围（含「不做」）、§1.4 范围穷举与存量面处置 |
| spec | `spec/{be,fe,qa,ui}/*.md` | 按适用轨道冻结行为、字段、失败路径及验收点（AC 表） |
| 设计 | `design/{be,fe,qa,ui}/*.md` | 按适用轨道给出结构、交互、接口、验证策略和异常分支 |
| 计划 | `plan/execution.md` | 任务看板（状态 / 依赖 / 证据回写）、回滚点顺序 |
| 实施 | 代码 + `plan/` 回写 | 已接受任务的状态与证据回写 |

## 提案与计划中的决策

1. full 立项打 `agentflow 目标承接` 标记时，同时写目标承接表；light 在 README 维护同义的需求→任务→用例→证据关系，不另建聚合副本。宣布完成的任务必须引用可复核证据，见下文「完成证据」。
2. 产品语义的未决分支一律先交用户（一行问题带推荐，提问纪律见[契约](contracts.md)的「先问再假设」节）。
3. 把未决事项留在用户已授权的单一决策载体；方案、任务或验收受到影响时引用该事项。阶段文档保留已定结论与来源。

## 原型与页面预览

UI 任务先用能回答产品问题的可交互预览确认受影响入口与状态，再冻结对应规格。小 UI 可直接用真实页面预览并浏览器验证，在 light README 留存确认与证据，不强制新建离线原型。新交互尚无可运行页面、用户明确要求原型，或 full 的交互风险需要单独验证时，按 [`templates/feature/prototype/README.md`](../templates/feature/prototype/README.md) 选择既有原型库或批次原型，先取得对应写范围授权；不得为满足形式重复造一份页面。无 UI 写 `N/A: 无 UI`。

## 埋点三处贯通

走文档交付链且涉及用户行为事件时，埋点在三处连成一线：`proposal` 的埋点决策 → `spec/fe` 的口径 → `design/fe` 的事件契约，验收落在 QA；三处互相矛盾、或任一处缺席，按缺口处理而不是可选装饰。事件手册不与档案链重复：沿链工作的项目，`design/fe` 的契约节就是它的事件手册；目标仓本就既有手册时以后者为准，契约节只登记本期的差异与出处。

## 阶段评审与完成证据

full 按[角色路由](roles.md#阶段--角色速查文档链)组织提案、规格、设计、计划。Reviewer 按
[文档入口](contracts.md#按对象核对入口)审查已冻结的阶段材料：提案看范围和取舍，规格看可执行的验收，设计看失败恢复和契约，计划看真实依赖、验证与回退。可把相邻已就绪的阶段放入同一简报，仍逐一给结论。后续产品验证和计划任务无需提前完成。light 在 README 保持同义证据定位。

完成行的证据接受：① 当前可读的项目文件与原始输出；② `仓库@revision:路径`；③ 可解析提交；④ `N/A: 具体理由与出处`。临时目录中将消失且无持久引用的内容、泛称「已验证」与仅勾选均不够；已获授权 README 可以内嵌原始输出及评审/run 引用。无工具时按人工清单核对并如实记录，不能声称自动门通过。

## 计划状态与交付状态

计划整体状态为 `draft → proposed → approved`，或进入 `superseded`。`approved` 表示计划本身已获接受；代码、发布和合并仍按各自权限与证据处理。只有计划作者之外的主审可批准；主审是作者时，交独立 Reviewer 或用户判断，用户的范围确认不能冒用独审结论。

逐任务状态为 `☐` 未开始、`◐` 进行中、`☑` 此任务的交付物与必需检查已核对、`⚠` 阻塞、`—` 不适用（附理由）。实现任务的 `☑` 指完成实现条目及其自检，不表示评审完成或功能获批。独审、收口是后继任务，按自身证据更新。任务 ID 始终沿用原计划，变更范围时按目标仓既有约定修订计划。

评审文档时使用 `--review-type document`。评审实现时使用 `--review-type implementation`，按
[评审任务映射](contracts.md#任务状态快照的来源)核对受评任务及前置；后继保持真实状态，避免用假勾选换取准入。整个交付仍按[最终决策记录](contracts.md#最终决策记录)的 `complete` / `partial` / `blocked` 判定。

## 表达纪律

面向人的规则、规格与结论先用白话；术语首次出现解释，内部代号必须有可定位出处。同一事实只保留一个正文来源，其它位置用指针；历史与当前、策略与本轮执行、作者自检与独立评审要明确区分。不得用「规范已普遍提效」替代测量；无仪器化结果写 `measurement: none`。

## 视觉基线三档

UI 轨启用时，视觉基线分三档——A 复用本仓既有基线（默认）、B 跨项目移植（逐项列差异）、C 冷启动才新建「基线 v1」。用[视觉设计模板](../templates/feature/design/ui/visual.md)说明来源、适用范围和差异；另行制作原型时按[原型模板](../templates/feature/prototype/README.md)选择落点。
