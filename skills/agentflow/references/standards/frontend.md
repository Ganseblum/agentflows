# 前端工程内容标准（agentflow 通用底线）

> **定位**：与 `server-side.md` 配套的前端底线。agentflow 的 `design/fe` / `spec/fe` 已给骨架，本册补**组件 / 状态 / 表单 / 可访问性**的硬判据。
> **来源**：吸收 youc《前端工程规范》《前端与服务端命名目录迁移约定》《原型交互完备性约定》。项目有更强规范时以项目为准。

## 0. 适用范围

`design/fe`、`spec/fe`、任何前端代码实现、前端代码评审、UI bug 修复。

## 1. 状态管理单一真源

**MUST**
- 表单 / 组件状态有**单一真源**，不出现「input 受控值」与「显示值」两套导致不同步（点名问题：remember 开关未受控、占位入口未移除）。
- 跨组件共享状态用明确机制（context / store / 提升 state），不靠 DOM 读值或全局变量偷偷传。
- 异步状态区分 `idle / loading / success / error`，不无限 loading 也不静默失败。

## 2. 表单与校验

**MUST**
- 所有用户输入在**提交边界**做校验，错误信息就近展示、可访问（关联 `aria` / `role`）。
- 防抖 / 节流：搜索、发信、验证码等高频触发动作必须防抖或限频，明确防抖窗口（如「发送验证码 60s 冷却」）。
- 提交按钮在请求中 disabled，防止重复提交（与服务端幂等协同）。

## 3. 错误与边界

**MUST**
- 全局错误边界捕获渲染异常，不白屏；关键路径失败有兜底 UI 与重试入口。
- 网络 / 业务错误区分展示，业务错误用服务端固定文案，不把堆栈 / 技术错误抛给用户。
- 加载态、空态、失败态齐备，不只有「正常态」。

## 4. 三方登录 / SSO 的 UI 边界

**MUST**（呼应 intake 范围维度）：若功能涉及三方登录（微信 / QQ / Google / GitHub 等），UI 必须明确：
- 三方入口的可见性与「未配置时的降级」（占位还是隐藏）；
- 回跳 / 回调页、深链、失败回退路径均有 UI 与状态；
- 与自有账号体系的账号绑定 / 解绑边界。

## 5. 命名与目录

**SHOULD**：组件 / 文件 / 状态名表达意图，遵循项目既有约定（与 youc《前端与服务端命名目录迁移约定》对齐）；不造黑话缩写。

## 6. 可访问性（a11y）

**SHOULD**：交互元素可键盘操作、有可读标签、颜色对比达标；错误文案不只是颜色区分。

## 7. Reviewer 自检清单

- [ ] 表单 / 关键开关受控，无双真源
- [ ] 提交 / 高频动作有防抖或限频
- [ ] 加载 / 空 / 失败三态齐备，有错误边界
- [ ] 业务错误用固定文案，无技术堆栈外露
- [ ] 若有三方登录，回跳 / 降级 / 绑定边界已覆盖
- [ ] 命名表达意图，无黑话
