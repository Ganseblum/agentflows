# 前端工程内容标准（agentflow 通用底线）

> **定位**：与 `server-side.md` 配套的前端底线。agentflow 的 `design/fe` / `spec/fe` 已给骨架，本册补**组件 / 状态 / 表单 / 可访问性**的硬判据。
> **来源**：吸收 youc《前端工程规范》《前端与服务端命名目录迁移约定》《原型交互完备性约定》，并按 2026-11-02 登录批次的实测结论修正了防连点条款。项目有更强规范时以项目为准。
> **编号**：`FE-01…FE-13`，供 reviewer 在 finding 里直接引用（与 `server-side.md` 的 `BE-*`、`data-model.md` 的 `DB-*` 同一体系）。

## 0. 适用范围

`design/fe`、`spec/fe`、任何前端代码实现、前端代码评审、UI bug 修复。

## 1. 状态管理单一真源（FE-01）

**MUST**
- 表单 / 组件状态有**单一真源**，不出现「受控值」与「显示值」两套导致不同步（典型缺陷：开关未受控、清空后仍回显旧值）。
- 跨组件共享状态用明确机制（context / store / 提升 state），不靠 DOM 读值或全局变量偷偷传。
- 异步状态区分 `idle / loading / success / error`，不无限 loading 也不静默失败。

## 2. 表单提交与防重复（FE-02）

**MUST**
- 所有用户输入在**提交边界**做校验，错误信息就近展示、可访问（关联 `aria` / `role`）。
- **重复提交不产生未授权的重复副作用**：覆盖真实入口的快速重复操作、并发与失败后恢复，并用请求/副作用证据证明约束成立。按目标框架、版本与事件调度选择同步占用标志、框架提交机制、禁用态或等效实现；React `useRef` 只是在需要同步占用时的一个例子，不是唯一方案。不能仅凭 `setState` 异步推导所有双击必然发两次请求，也不能仅看 `disabled` 就宣称安全；技术因果未实测时标假设，按实际事件与请求日志核验。
- 防抖 / 节流：搜索、发信、验证码等高频触发动作必须防抖或限频，明确防抖窗口（如「发送验证码 60s 冷却」）。防抖解决「连续触发」，同步锁解决「并发重复提交」，两者不能互相替代。

## 3. 错误与边界（FE-03）

**MUST**
- 全局错误边界捕获渲染异常，不白屏；关键路径失败有兜底 UI 与重试入口。
- 网络 / 业务错误区分展示，业务错误用服务端固定文案，不把堆栈 / 技术错误抛给用户。
- 加载态、空态、失败态齐备，不只有「正常态」。

## 4. 三方登录 / SSO 的 UI 边界（FE-04）

**MUST**（呼应 intake 范围维度）：若功能涉及三方登录（微信 / QQ / Google / GitHub 等），UI 必须明确：
- 三方入口的可见性与「未配置时的降级」（占位还是隐藏）；
- 回跳 / 回调页、深链、失败回退路径均有 UI 与状态；
- 与自有账号体系的账号绑定 / 解绑边界。

## 5. 请求生命周期（FE-05）

**MUST**
- 请求携带取消信号，或完成后校验请求身份：参数变化、卸载、身份切换后，**晚到响应不得覆盖新状态**。
- 监听 / 定时器 / 订阅 / Observer / 对象 URL 都有释放方；卸载后的回调不写状态。
- 缓存键含分页、排序、筛选与作用域（用户 / 租户 / 产品），请求参数与键用同一份规范化结果。

## 6. 契约字段与类型边界（FE-06）

**MUST**
- 字段按契约区分省略、`null`、空串、零值与空数组，**不用 `value || fallback` 吞掉有效零值**。
- 金额、点数与大整数保留既定单位与精度；时间区分时间点与自然日期及时区；未知枚举显式处理。
- 外部输入从 `unknown` 收敛并校验，不靠 `any`、非空断言或双重断言绕过契约。

## 7. 命名与目录（FE-07）

**SHOULD**：组件 / 文件 / 状态名表达意图，遵循项目既有约定；不造黑话缩写；不引入并行目录（`services` / `models` / `helpers`）或第二套 UI 框架。

## 8. 可访问性（FE-08）

**SHOULD**：交互元素可键盘操作、有可读标签、颜色对比达标；错误文案不只是颜色区分；弹层关闭后焦点合理恢复。

## 9. 副作用与资源清理守卫（FE-10）

**MUST**（吸收 `scan-lifecycle-guard` 硬指标，杜绝内存泄漏与僵尸回调）：
- **显式清理契约**：所有在组件生命周期中建立的长驻资源，必须在卸载回调（React `useEffect` return cleanup / Vue `onUnmounted`）中成对销毁：
  - 定时器：`setInterval`、`setTimeout` 必须调用 `clearInterval` / `clearTimeout`。
  - DOM 与全局事件：`window.addEventListener` / `document.addEventListener` 必须在清理函数中用同一引用 `removeEventListener`。
  - 长连接与推送：WebSocket、EventSource (SSE)、BroadcastChannel 必须在卸载时显式 `close()`。
  - 观察器与监听：`ResizeObserver`、`IntersectionObserver`、`MutationObserver` 必须调用 `disconnect()`。
  - 对象 URL：`URL.createObjectURL(blob)` 必须成对调用 `URL.revokeObjectURL(url)` 释放浏览器内存。
- **防止卸载后异步写状态（Zombie State Update）**：
  - 异步请求、延时逻辑或三方回调必须使用 `AbortController` 绑定生命周期，或在组件卸载后阻断状态变更，严禁在已卸载组件上触发 `setState` 导致内存泄漏或控制台报错。

## 10. 国际化与文案键值完整性（FE-11）

**MUST**（吸收 `i18n-audit` 硬指标）：
- **零硬编码文本**：所有面向用户的提示、按钮、标题、占位符、错误反馈必须通过统一 i18n 方法（如 `t('module.feature.key')`）调用，严禁在 JSX / 模板内散落裸中英文字符串。
- **语言包对称性（Parity）**：新增或修改 i18n key 时，必须保证所有支持语言包（如 `zh-CN.json`、`en-US.json`）对齐，不得出现单语言缺失导致直接向用户暴露 `auth.login.btn_submit` 裸 Key。
- **动态插值类型约束**：文案包含占位符时（如 `共 {count} 条数据`），插值变量必须强类型化并显式传递，严禁因缺参渲染出 `共 undefined 条数据`。

## 11. 视觉方向与首屏层级（FE-12）

**MUST**（吸收 `frontend-design` 的判断顺序；只在视觉质量本身是成功标准时适用）：
- 编码前先写一句**视觉主张**：这个页面要让用户第一眼感到什么、记住什么；没有这句话就不进入组件拆分。
- 首屏必须能回答「这是什么、给谁、下一步做什么」：品牌/产品名可见，主行动明确，信息层级按标题 → 副标题 → 主体 → 辅助细节展开。
- 禁止默认卡片堆砌、弱品牌、弱首屏和 UI 噪音；区块、分栏、分隔、列表、媒体块与留白优先于重复卡片。
- 全幅首屏必须真正 edge-to-edge；图片上文字必须有稳定的暗区/亮区保证对比，不能把正文直接压在高噪图片上。
- 产品/工作台界面以工作区优先，不用营销式 hero 替代核心操作；内容密度可以高，但层级必须清楚。
- 影像与动效先定策略：图片承担叙事还是装饰、动效解释状态还是装饰；没有策略就不加。
- 不适用：普通后台 CRUD、纯样式小修、已有设计稿照图实现、纯 bugfix。

## 12. 设计稿还原与走查（FE-13）

**MUST**（吸收 `design-walkthrough` / `mastergo-*` 的证据纪律；有设计源且要交付 UI 时适用）：
- **先定设计源与 revision**：链接、画板/图层 ID、版本或快照；没有设计源时按目标仓视觉基线走 FE-12，不假装走查。
- **设计侧截图必须是画板的 1× PNG 导出**，不能用编辑器整页截图（带图层树/标注栏/缩放标尺的一律不合格）。
- **实现侧截图按画板尺寸设置 viewport 精确截取**；两侧并排放在同一份 `comparison.html` 里，禁止留 placeholder 让用户自己塞图。
- **逐变体对照**：同一组件的不同变体、图标、字色/阴影/透明度、图片资产、固定宽高与多语言自适应逐项核对；结论必须写明「哪种变体、设计层 ID、代码落点、path/fill 是否一致」，不能只写「看起来差不多」。
- **设计组件到代码的映射**：重复使用的设计组件有多个变体，或设计属性会改变用户可见状态时，在 UI 设计表记录受影响的设计节点与属性值、真实组件路径和对应 prop 值。核对实现类型或组件接口，逐项说明复用、组合或有意差异。设计属性无直接代码等价项时，写明渲染依据或未覆盖状态及处置。
- **DSL 字段陷阱**：按设计工具实际返回的字段解释；看不清的 layer 再取一次 DSL，不靠肉眼猜。
- **资产先行**：设计源含图片/图标时，先导出资产并登记 manifest，再落码；禁止在实现里用占位图冒充。
- 完成标准：`comparison.html` 打开即看到两张真实截图并排；变体表填满；无 placeholder；差异逐条分级（P0/P1/P2）并给出处置。
- 不适用：纯代码评审、没有设计源的 UI 调整、只做 C2D 回写。

## 13. Reviewer 自检清单（FE-09）

- [ ] 表单 / 关键开关受控，无双真源（FE-01）
- [ ] 快速重复、并发与恢复场景下无重复副作用，实际框架/版本的证据支持所选防重方案（FE-02）
- [ ] 高频动作有防抖窗口（FE-02）
- [ ] 加载 / 空 / 失败三态齐备，有错误边界（FE-03）
- [ ] 业务错误用固定文案，无技术堆栈外露（FE-03）
- [ ] 若有三方登录，回跳 / 降级 / 绑定边界已覆盖（FE-04）
- [ ] 晚到响应不覆盖新状态，监听 / 定时器有释放（FE-05）
- [ ] 契约字段的省略 / `null` / 零值区分处理（FE-06）
- [ ] 命名表达意图，无黑话、无并行框架（FE-07）
- [ ] 副作用资源（定时器、事件监听、Observer、WebSocket、对象URL）具备严格成对清理，无卸载后写状态（FE-10）
- [ ] 无页面裸硬编码文案，多语言 key 对齐且无缺失（FE-11）
- [ ] 视觉主张与首屏层级明确，无默认卡片堆砌/弱首屏（FE-12）
- [ ] 有设计源时完成 1× 导出、精确 viewport、逐变体对照，无 placeholder（FE-13）

> finding 引用本册时写编号（如「违反 FE-02：重复提交产生两次副作用，见实际运行证据」或「违反 FE-10：setInterval 未在 cleanup 中销毁」），不给只写文件名的 finding。
