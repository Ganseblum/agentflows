# 数据模型设计标准（agentflow 通用底线）

> **定位**：与 `server-side.md` 配套的**存储 / 数据结构**底线。agentflow 的 `design/be` §1.3 与 `spec/be` §1.1 已给骨架，本册给**字段级必须冻结的内容标准**，防止「spec 只列关键字段、design 才补类型」导致的口头约定漂移。
>
> **来源**：吸收 youc《数据库设计与SQL规范》（DB-17 先定义实体不变量、DB-23/24/25 字段与索引、DB-45 幂等键）。项目有更强规范时以项目为准。

## 0. 适用范围

- `spec/be` §1.1 的「核心对象」必须升级为**完整字段契约**（不仅是关键字段）。
- `design/be` §1.3 的 DDL / 等效结构契约必须逐字段满足本册。
- **内存态 / KV / 缓存 / 前端状态**也视为「数据模型」，即便无真实 DB，也要写**等效结构契约**（类型 / 单位 / 空值 / 唯一性 / 索引等价物 / 幂等键），不得写「无 DDL 即免写字段定义」。

## 1. 实体不变量先于表（DB-17）

**MUST**：先定义每个实体的**不变量**（什么永远为真），再选表 / 字段。不变量写进 `spec/be`，如「一个用户只有一个生效会话」「token 过期即失效」。表结构只是不变量的载体，不是反过来。

## 2. 字段完整定义（DB-25）

**MUST**：每个字段在 `design/be` §1.3.2 / `spec/be` 给出：

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| 字段名 | ✓ | 命名表达语义 |
| 类型 | ✓ | 精确类型（不写 `string`，写 `varchar(64)` / `bigint` / `timestamptz`） |
| 长度 / 精度 | ✓ | 字符长度与字节长度不混用 |
| 单位 | ✓（数值类） | 秒 / 毫秒、字节 / KB 显式区分 |
| 空值 | ✓ | 可空 / 非空及理由 |
| 默认值 | ✓ | 有 / 无默认及来源 |
| 取值范围 | 视情况 | 枚举全列出、数值上下界 |
| 唯一性 | ✓ | 唯一约束 / 联合唯一 |
| 敏感性 | ✓ | 密码 / token / PII 须标注，不得明文存储 |
| 索引等价物 | 视情况 | 内存态标注「以 X 为查询键」 |

**禁止**：只写「id、email、passwordHash」这类无类型 / 无约束的「关键字段表格」充当数据模型。

## 3. 索引与查询（DB-24）

**MUST**：每个高频查询标注命中的索引；列出查询组合与对应索引；分页必须稳定（有确定排序键）。无 N+1 / 无无界扫描；批查有规模上限与部分失败语义。

## 4. 幂等键作用域与一致性（DB-45）

**MUST**：若接口依赖幂等（见 `server-side.md` §1），写明幂等键的**作用域**（单实例 / 集群 / 跨服务）、**一致性**（同键在 TTL 内返回首结果）、**保留期**（如 24h）。内存态 demo 也须声明等效机制（如「以 clientToken 去重，进程内缓存」）。

## 5. 迁移与向后兼容

**MUST**：新增 / 修改表字段级 SQL 带迁移命名、回填策略与回滚；迁移在**真实库**上验收，不只在 dry-run。破坏性变更（删字段 / 改类型）必须有 deprecation 窗口或版本边界（与 `design/be` §1.6 联动）。

## 6. Reviewer 自检清单

- [ ] 每个实体有不变量声明
- [ ] 每个字段有类型 / 空值 / 默认 / 单位 / 唯一性
- [ ] 敏感字段标注且未明文存储
- [ ] 高频查询有索引、分页稳定
- [ ] 幂等键作用域 / 一致性 / 保留期已定义
- [ ] 迁移有命名 / 回填 / 回滚且真实库验收
- [ ] 内存态也写了等效结构契约（非「无 DDL 免写」）
