# issues — 缺陷与事项流

> 规则：编号 `<ISS-<YYYY-MM-DD>-<slug>｜沿用项目既有编号规则>`；开放条目平铺于本目录，关闭或被拒条目移入 `归档/<日期>/`。小修在条目内解决；中/大问题经用户确认后升格为 `features/` 批次。

## 开放条目

| 编号 | 标题 | 状态 | 归属 |
| --- | --- | --- | --- |
| ISS-YYYY-MM-DD-<slug> | <一句话现象> | open | <负责人 / 关联批次> |

> 状态只写 `open` / `fixed-pending-review` / `verified` / `rejected`；状态权威在每条记录的 frontmatter，本表只是索引，不在行内写状态结论散文。详细规则与记录形态见 `docs/issues/README.md`。

## 升格通道

- 中/大问题经用户确认后，在 `features/` 下建批次；原记录的状态节写「已升格并入 `<批次目录>`」，批次 README 写「升格来源：ISS-YYYY-MM-DD-slug（原由）」。
- 升格即留痕，不靠记忆。

## 归档

- 被拒记录移入 `归档/<YYYY-MM-DD>/`，原记录正文注明拒绝理由与出处。
- 归档是记录面的归档，不是 git 历史的替代；删除类操作仍以 git 历史为回溯依据。
