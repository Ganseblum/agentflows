# 目标仓 AGENTS.md「Agentflow 接入约定」节

Init（首次接入）写入目标仓 `AGENTS.md` 的固定骨架：固定块写跨项目成立的硬判据，槽位由
接入六问的答案填充。协议见 [SKILL.md](../../SKILL.md) 的「首次接入」节，与宿主级规则的
边界见 [hosts.md](../../references/hosts.md)。本文件由 `python3 tools/lab/validate.py docs`
校验：模板存在、begin / end 标记齐全、三句门条款在场、SKILL.md 指向本模板。

## 模板正文

```markdown
<!-- agentflow:repo-rules:begin v{{version}} -->
## Agentflow 接入约定

本节约束本仓所有 AI / 自动化会话。它只放**本仓的硬判据与实例**；方法、模板与角色契约在
Agentflow 插件的 skills 里，不在这里重复。宿主级规则（写前确认分支、合并 / 推送两次授权）
在宿主指令文件的托管块中，本节只写本仓实例与增量。重跑 Init 时整节替换，标记外一字不动。

### 1. 交付与表达

- 交付语言：<默认中文>；面向用户的文档与报告白话优先，内部自造词首次出现用一句话解释或换白话。
- 术语：<用户反复纠正过的词 → 统一说法；如「台账」→「清单 / 记录」>。

### 2. 分支与集成（本仓实例）

- 分支前缀：<codex/<主题> | feature-<主题> | fix-<主题> | sync/<主题> | release_*；全小写、连字符分隔>。
- 不直接开发的受保护分支：<main / master / release_*>；只从经过验收的 <main> 提交或打 tag 发布。
- 一次任务中切换过分支后，后续每次写操作重新确认当前分支。
- 合并、变基、跨分支 cherry-pick、推送被拒后的集成：逐次取得当次确认；先只做只读的
  `git fetch` / `git log` / `git diff`，把「远程多了什么、与本地的重叠在哪」讲清楚再由用户选方式。

### 3. 写操作红线

- 写前先 `git rev-parse --abbrev-ref HEAD`；发现「先改后查」立即停下报告，不继续提交或推送。
- 工作区已有改动不回滚、不覆盖；多会话共用同一工作树时先看 `git status` 与文件修改时间，
  等对方落盘再动，不混提交。
- 禁止用脚本（`python` / `str.replace` 等）对源码做整段替换；用编辑工具改，改完跑对应用例。
- 故障注入、变异测试只在 `/tmp` 的一次性副本上做；不得用 `git checkout` / `git restore`
  撤销真实树上的实验。
- 门与契约：<受保护路径清单或入口>、记录 schema、发布策略的修改属门变更，须人工评审授权；
  不得通过删标记、绕过检查转绿。

### 4. 验证与证据

- 仓库检查命令：<构建 / 单测 / lint 的完整命令；含运行环境要求，如 Python 3.11+>。
- 文档链门（新批次建好当天跑一次；宣布任何批次完成前对全仓批次再跑一遍并贴原始输出；
  在**本仓根目录**运行——位置参数相对当前目录解析，不相对 `--root`）：
  `python3 <插件根>/tools/lab/doc_chain.py --root <本仓根> <feature-dir>`。
  finding 要么修，要么在 <豁免登记位置> 写明理由与承接任务，不许口头绕过。
- 仓库自带门：<脚本命令 + 期望输出形态>。
- 证据纪律：检查 / 验收脚本必须先打印命中原文再判 PASS/FAIL；否定式表述与验收条目自身的
  引用式命中要排除；存在性结论不得用裸 `grep`（中文关键词会静默漏报），用可计数、可打印
  命中文件与计数的脚本；无法复现的检查记为未运行，绝不计为通过；未观察到的恢复不算恢复；
  不得声称走查过自己未观察到的宿主行为。

### 5. 文档与记录落点

- 文档中枢：<路径>；唯一索引：<路径>。新增、移动、删除文档在同一变更中更新索引。
- 记录：缺陷与事项用 <issues 形态>，编号形如 `<id 形态>`，关闭后归档到 <归档规则>；成批工作立
  <features 路径> 批次；待验收登记 <pending-test 路径>；决策记录（拍板口）<目标仓文档枢纽/拍板口路径，如 `docs/PENDING-DECISIONS.md`>。
- 新增顶层目录或新的文档类型须先经用户确认，不得自行创建。

### 6. 工程基线

- 入口：<已有规范路径，或本次落下的基线文件路径>。实现前先读；基线与任务冲突或缺口时
  按「先问再假设」停下，不按通用默认推进。

### 7. 沉淀

- 同一注意事项被用户指出第二次，当轮把它写成明确、可执行的条款补进本节，不写模糊描述。
<!-- agentflow:repo-rules:end -->
```

## 填写与写入规则

1. `<...>` 是槽位，由接入六问（语言与读者、术语、分支与合并纪律、检查命令、文档与记录
   落点、工程基线）的答案填充；某项不适用写 `N/A: <理由>`，不删小节。
2. 固定块只写跨项目成立的硬判据；仓库特有事实一律进槽位。角色分工、文档链内容要求、
   模板形态留在插件 skills。
3. 目标仓已有 `AGENTS.md`：整节追加在文件末尾，保留 begin / end 标记；重跑 Init 只替换
   标记内内容，标记外一字不动。没有 `AGENTS.md`：先征得同意再创建。
4. 版本号取插件 manifest 版本；模板变更必须同时 bump 插件版本，否则同版本重跑是空操作。
5. 写入后按确认单核对，并在接入报告里逐项答复：七节都有值或 `N/A: 理由`；三句门条款
   齐全（当天跑门、完成前全量跑门并贴原始输出、finding 修或登记）；工程基线入口有路径；
   分支前缀与记录编号形态是本仓实测事实，不是通用默认。
