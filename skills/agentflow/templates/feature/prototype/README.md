# `prototype/` — 可直开线框与一次性原型

> 一句话：谈不出来的问题（长什么样、怎么走）用这张页面回答，不要用形容词来回拉扯。
> 复制 `index.html` 到 feature 目录的 `prototype/` 下，浏览器双击直开——没有构建链、没有依赖、
> 不发网络请求。

## 两个档位（在文件标题旁标注用了哪一档）

| 档位 | 形态 | 什么时候用 | 评审看什么 |
| --- | --- | --- | --- |
| 结构稿（wireframe） | 灰线框 + 区块标注，四态切换 | 默认。页面结构、入口位置、字段顺序、状态兜底 | 结构是否成立、有没有遗漏状态 |
| 可点原型（prototype） | 在结构稿上接假数据，能点通主流程 | 主流程步骤多、或需要和用户确认交互手感 | 步骤数、跳转去向、放弃路径 |

两档都**不是最终视觉**：颜色、字体、圆角、动效不参与结论，视觉结论走 `design/ui`。
上面两档也不替代 `design/fe §1.1.5` 的线框表——表里逐条写“这个区块承担什么 + 挂哪个
testid + 结论”，页面只负责让人看见结构。

## 命名与落点

```text
<feature 目录>/
  prototype/
    index.html          页面入口（复制骨架后改，不新建第二个入口）
    states.md           可选：四态与边界态的截图/说明，页面里放不下时用它兜
```

- 文件名固定 `index.html`：README 元信息与 design 文档都指向它，避免每个批次换个名字。
- 一个页面一个 `<section class="screen">`，页签自动生成；新增页面不改脚本。
- 页面里出现的可点击元素，在 `design/fe` 的 testid 清单里必须有同名条目——原型与实现用同一套
  testid，测试用例才能直接引用。

## 真源声明（必须写，只写一处）

在 `design/fe` 或 `design/ui` 的线框节头部声明一次，不要两处各画一份：

```text
线框真源：prototype/index.html（结构）+ design/fe §1.1.5 线框表（标注与结论）
冲突时以本节表格的文字结论为准，页面图作为结构证据保留。
```

## 结论回写

原型是提问出口，不是交付终点：每个标注项都要在提案的待冻结问题台账或 spec 里落成一行结论
（哪个方案对、为什么），并带上判定口径。页面本身按上面的路径留作证据，**不要在结论落账后
删除**——它同时是 QA 理解页面结构的依据。

## 什么时候可以 `N/A`

- 本 feature 没有用户可见界面（纯后端、纯脚本、纯文档）：在 `README` 元信息写
  `原型：N/A: 无用户界面`。
- 视觉与结构完全复用既有页面、无新增区块：写 `原型：N/A: 复用 <页面> 既有结构，见 <链接>`，
  并在 `design/fe` 的线框表里逐条写明复用哪一块。
