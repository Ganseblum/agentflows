# 决策简报模板（给 owner 的完整决策文档）

> **用途**：产品决策不要只给「推荐 A」。给 owner 的简报固定「分类头 + 九段」，让没跟过流程的人也能拍板。
> 本模板**不是门**（不强制机器判），只给形状；内容质量由评审门把关。
> 路由已挂进 `skills/agentflow/SKILL.md` 的「先读哪份规则」表：用户要做正式的产品决策简报时用本模板。
> 与「先问再假设」的分工：访谈前沿的一行问题（≤3 选项、带推荐项）不换成本模板——那是对话节奏；
> 只有已登记进拍板口、需要 owner 逐字段核对的正式决策，才展开成本模板的分类头 + 九段。

## 形状

```markdown
### <编号> · <一句话标题>
> 优先级: P2 | 影响范围: 多模块(youc-admin 订单筛选页 + youc-canvas 支付组件) | 自动决策: 否(人工)

**来源**：<需求文档 path:line> / <ISS 编号> / <批次任务号>
**出现在哪**：<文档 path:line>；<代码 path:line>；<用户可见处：页面 / 接口>
**发生了什么**：<机制一句话 + 现状：哪天核过、怎么核的>
**影响**：<谁受影响、什么时候发生、不处理会怎样——具体到「谁会在哪个页面看到什么」>
**选项对比（≥3）**：
| 选项 | 要动什么 | 采纳后（做） | 不采纳（不做 / 维持现状） | 代价 / 风险 |
| A <名称> | <改动点> | <做之后的状态> | <不做时维持的痛点> | <成本/风险> |
| B <名称> | <改动点> | … | … | … |
| C <名称> | <改动点> | … | … | … |
**建议**：<选哪个 + 为什么，不超三句，必须呼应影响段>
**优先级与影响范围**：<P 评级依据 + 波及面：是否跨项目、是否碰核心链路>
**是否可自动决策 + 决策理由**：<可自动：写预设规则 / 触发条件 / 本次由谁(规则)依据什么判定；
  不可自动：写为何不能交给预设规则(涉及取舍/翻译/外部依赖)>
**拍板后动作**：<编号清单，含验证方式：跑什么、看什么>
```

## 各段「及格线」

1. **分类头（优先级 / 影响范围 / 自动决策）**：三值必填；优先级按 P0–P3 枚举，影响范围格式为 `级别(具体模块/项目，逗号分隔)`，**禁止只写级别词**（如只写「单模块」而不列具体模块 → 不合格）；自动决策 Y 仅限 P3。
2. **来源**：必须能回溯到需求 / 文档 / 批次，不能只写「#96」。
3. **出现在哪**：代码要 `path:line`，用户侧要指明页面或接口——不能只说「系统里」。
4. **发生了什么**：带核验日期与方式（命令或查询），证明不是凭记忆写的。
5. **影响**：写到「人 + 页面 + 现象」三级，避免「可能有问题」这类模糊句。
6. **选项对比**：**至少 3 个选项**；每行必须同时写「采纳后（做）」与「不采纳（不做）」两种后果 + 代价。只给选项名不给后果的，等于没给。
7. **建议**：三句内，且结论必须呼应「影响」段。
8. **优先级与影响范围**：明示评级理由与**具体波及面**（列出涉及的模块/项目名，不能只说「多模块」），让评审一眼知道「这事动哪、多大」。
9. **自动决策 + 理由**：即便标 Y，也要写清预设规则与本次判定依据；标 N 要写清为何不能自动化。

## 反例（不合格）

```markdown
### R6 渠道知识
建议收敛成单一注册表。
```
→ 分类头缺、选项只有一句、无做/不做后果、无影响范围 → 退回补写。
