## 二、关键结论（据此定改动方向）

1. **输出 token 里 97.5% 是推理**，可见正文不到 1%。故**不设任何 token 或读取上限**——压输出等于砍判断力。
2. **工具执行只占 2%**，读文件本身不是瓶颈。瓶颈是每轮重付一次首字等待 + 一次对已读内容的重新推理。
3. **43.6% 的轮次花在「找位置」**，不是「判断对不对」。
4. **27% 的 Read 是重读同一文件**；有上下文压缩的会话 19.8%、无压缩 13.8%。

## 五、复测时怎么比

1. 重装插件后（`validate.py installed` 需转 PASS），让规则真正生效；未重装前的评审仍走旧快照，数据不可比。
2. 用同一命令复测：`python3.12 tools/review-cost-baseline.py --since <重装后日期>`。
3. 对比这五项即可判断是否见效：
   - 中位会话时长（基线 24.5 分钟）
   - 检索轮占比（基线 43.6%）
   - 重复读次数（基线 9）
   - **唯一文件数（基线 37）——这一项必须不下降**，它下降说明读取范围被压了
   - 推理字符占比（基线 97.5%）——若明显下降，说明判断量被砍了

**判据**：前四项改善且唯一文件数不降，才算改对了；唯一文件数下降或推理占比明显下降，都是压过头的信号，应回退。
