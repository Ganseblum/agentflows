## 七、怎么迭代升级优化

### 第 0 步：先拍板三件事（不写文件）

1. **状态枚举口径**：Youc 的裸字形 vs 0.11.0 的「字形 + 标签」。**建议改 Youc 侧**——
   批量替换成本低；改门等于改 46 个自测和 78 个单测钉住的契约，属门变更，要你显式授权。
2. **代码落点路径基准**：相对 Youc 仓根 / 相对 `youc-workflow-ai/` / 相对批次。不定这条，
   C9 的 89 处落点发现永远是噪声。
3. **范围**：27 个批次全修、只修活跃、还是只对新批次生效。**建议第三者**——
   历史记录不回改是 agentflow 自己的硬边界，全修等于推翻自己。

### 第 1 步：让"跑门"成为 Youc 的明文规则（最小动作，最高杠杆）

在 Youc 的 `AGENTS.md` 里，把「功能实现必须走 agentflow 主流程」补成三句可执行的话：

- 新批次建好当天，跑一次 `doc_chain.py --root <Youc> <feature-dir>`；
- 宣布任何批次完成前，全量批次跑一遍并贴输出；
- 输出里出现 finding 不许口头绕过，要么修要么登记。

**这一条不升级 agentflow 也能做，用的是 0.11.0 已发布版。A 类 7 条里有 6 条靠这一句就能消掉。**

### 第 2 步：建立可校验的版本基线

在 `youc-workflow-ai/index.md` 顶部加一行：

```text
形态对标 agentflow 0.11.0（plugin.json），最后核对 2026-10-21，
核对命令：python3 tools/lab/validate.py installed
```

然后把 agentflow 正式装成宿主插件（本地 marketplace 指向 `packaging/runtime`），
`validate.py installed` 才跑得起来，版本漂移才可发现。
注意：0.11.0 的 CHANGELOG 记着 `installed` 仍是红、需要你刷新 marketplace 重装——
这本身是个待办，不是装完就绿。

### 第 3 步：把未发布批的三套模板搬过来

从 `agentflows` 的 `skills/agentflow/templates/` 复制：

- `feature/prototype/{index.html,README.md}` → 治 C7 线框；
- proposal §6.2 埋点决策 + `spec/fe` §4 + `design/fe` §1.7 事件契约 → 治你 10-20 晚上人工做的那件事；
- `spec/ui` §2.1 / `design/ui` §0.1 视觉来源三档 → 治 UI 验收扯皮。

同步做 `proposal/prd.md` → `proposal/proposal.md` 一次性改名（27 个批次，含 README 链接）。

**再次提醒**：这三项目前只有模板没有门，接上也不会自动变红，别期待装了就灵。

### 第 4 步：把 Youc 自己踩过的坑立成 Youc 的门（最值钱的一步）

agentflow 能给的是文档链；Youc 的坑一半在代码和环境，只能自己立：

- **中文存在性检索必须用 Python**——已有硬规则，可落成 `scripts/` 里的检索脚本；
- **差异清单状态必须对代码复核**——T25 的 perm-drift 模式推广：清单条目 → 代码断言；
- **验收脚本必须先打印命中原文再判 PASS/FAIL**——10-21 两次同类误报（否定式表述被当成残留、
  compose 未指定 env-file 被当成缺变量）的教训，直接写成 Youc 的脚本规范；
- **deploy env 完整性自检**——`COMPOSE_PROJECT_NAME` 已做，可扩到 SSO client id、镜像 tag；
- **容器 IP 变更后必须 reload 前端 nginx**——已固化到文档，可写成部署脚本的一步。

### 不建议做的两件事

1. **不要为了"用上最新版"去改 agentflow 的门禁**（状态枚举、落点基准、埋点门）。
   那是门变更，按本仓规矩要你显式授权，而且会让 46 个自测和 78 个单测一起动。
2. **不要一次性把 27 个批次修到全 PASS。** 历史记录不回改是硬边界；而且 C9 那 392 处里
   一大半是口径噪声——先清口径再谈干净，否则门会因为你总视而不见而失效。
