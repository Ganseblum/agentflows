# 技术方案评审 — 产品线完善

## 评审范围

本批 技术方案评审(L2) 应当覆盖的四项设计点（取自 `PLAN-PRODUCT-001.md` 的「架构结论」与任务
T07/T08/T06）：

1. **架构结论** —— 方法插件而非运行时、14 角色是能力不是默认流水线、评测官/发布官是角色分离等。
2. **打包拆分（runtime vs lab）** —— 运行时面（skills/agents/manifest）与实验室面
   （tools/evals/tests/docs/计划文档/…）分开，消除整目录快照死重。
3. **默认路径缩短** —— Skill 强调只启用有工作的角色，14 角色留作可选能力。
4. **marketplace 快照一致性** —— `marketplace.json` 的 `source` 指向生成树，重装后安装快照与源码一致。

**实读核验的产物（均真实存在且自洽）：**

- `packaging/build_runtime.py`：`RUNTIME_DIRECTORIES`（`agents`/`skills`/`schemas`/各宿主
  plugin 目录）、`RUNTIME_SUBTREES`（`tools/lab/doc_chain.py`、`tools/lab/docchain`）、
  `RUNTIME_FILES`（`plugin.json`/`marketplace.json`/`protected-paths.txt`）、
  `FORBIDDEN_TOP_LEVEL`（issues/episodes/若干已退役顶层目录/`releases`/`reviews`/`tests`/`docs/`
  evals/examples/.git/packaging）。拆分即「运行时 vs 实验室」。另有 `assert_safe_destination`
  拒绝覆盖仓库根及其祖先、`copy_file`/`copy_tree` 拒绝符号链接、`build` 对 `RUNTIME_FILES`
  做 sha256 摘要比对、`verify` 校验禁止顶层与缺失项——安全与一致性护栏齐备，与
  `tools/lab/artifact_digest.py` 同规则。
- `skills/agentflow/SKILL.md`：Bind 段（第 12–18 行）**不再枚举 14 个 `agentflow:*`**，
  明确「默认不加载完整角色列表；插件根目录 `agents/` 下的角色文件是可选能力」，并给出
  ZCode/Qoder 重建生成树后重装、`validate.py installed` 查漂移的指引。默认路径已缩短。
- `skills/agentflow/references/roles.md`：路由表（第 47–66 行）「角色是能力，不是必走的阶段。
  只选择那些能降低风险或允许有效并行的角色」；「只取链上真正有工作的角色」。与默认路径缩短一致。
- `marketplace.json`：`source` 为 `"./packaging/runtime"`，即由 `build_runtime.py` 生成的
  运行时树；`version` 为 `0.23.0`。
