# 测试设计：全面修正与瘦身批（QA 轨）

## 1. 测试策略

本批没有运行期代码路径可跑端到端，「测试」= **判据级夹具** + **记录面改写前后的可数事实**两类。

| 层次 | 判据 | 为什么这样测 |
| --- | --- | --- |
| 夹具级（新增判据本身） | `doc_chain.py --self-test` 前缀式用例 + `tests/test_gate_records.py` 用例 | 新判据若只有正例没有负例，等于没有判别力——本仓 2026-09-20 的 `ISS-2026-09-20-文档链首轮密度缺口` 一类教训就记在这一点上 |
| 反证级（判据会不会被削弱） | 在 `/tmp` 一次性副本上删掉新判据，确认对应用例转红 | 与 2026-10-26 审核 G13「负例钉不住目标判据」同源的做法；故障注入只在副本运行，不在工作树 |
| 记录级 | 同一扫描脚本在「改写前 / 改写后 / 删除后」各跑一次，三个计数都进计划证据列 | 只有后置计数无法证明中间没有假绿；三个数才能证明顺序对（S3 → S4） |
| 面级 | `validate.py all`、`doc_chain.py <本批>`、`doc_chain_live`、`decision_gate` | 收敛类改动最容易在别处留下断链，用全仓面扫兜 |

## 3. 覆盖映射

`spec/qa/acceptance.md` §2 的十一个方向逐条对应到上表；本节只补充验收点之外的三项：

- **判据过宽方向**：`EV-05`、`C18-03` 两条专门钉「判据不许扩大到散文与非阻塞行」。
  首轮若这两条不红也不绿，说明判据没有边界意识，退回重写而不是放宽。
- **追溯性方向**：`RT-04` 钉住「存量记录不被新约束打红」。本仓的历史不回改是明文口径，
  判据必须自带这个豁免，否则会逼出「给批次摘标记转绿」的规避动作。
- **不可自动化方向**：`AGENTS.md` 与链契约新增的分工行、`carrier-map.md` 的行文质量、
  必读面收敛后的可读性，属阅读向判断，只能由独立评审与用户确认，不写成机器 AC。
