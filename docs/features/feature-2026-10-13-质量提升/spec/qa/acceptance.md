## 2. 冻结任务集草案（M-F 判据的前置条件）
本节为任务集草案，由用户在 Q-03 确认后冻结。草案中不含任何已执行的结果。冻结后不得增删任务，只能由用户另行批准修订。

| 任务 id | 类别 | 描述要点 | 验收命令形态 |
| --- | --- | --- | --- |
| T-01 | 单层小修 | 修复一个已知缺陷，并补回归测试 | 对应测试命令通过 |
| T-02 | 跨层功能 | 新增一个需要前后端协同的字段 | 集成测试通过 |
| T-03 | 文档交付 | 为一个给定功能产出 proposal 与 spec | 文档链检查退出码为 0 |
| T-04 | 评审发现 | 审阅一段含预埋缺陷的代码，列出缺陷 | 缺陷清单与预埋缺陷逐条对照 |

任务集中至少一半须为预埋缺陷类任务，否则无法计算漏检缺陷数。

## 4. 判据（预先写定，运行后不得修改）
| 判断项 | 通过条件 | 未满足时 |
| --- | --- | --- |
| 效果有提升 | 装插件一臂的漏检缺陷数中位数下降 ≥ 30%，耗时增幅 ≤ 50%，且三次重复的方向一致 | 不满足即判「无提升」，记录原始数据，不改判据 |
| 效果无提升 | 不满足「有提升」，且「未知」占比 ≤ 20% | 判「无提升」 |
| 无定论 | 「未知」占比 > 20% | 判「无定论」；补跑前须用户重新确认预算 |
| 禁止事项 | 不得剔除「未通过」或「未知」记录后再计算 | 违反则结论无效 |
