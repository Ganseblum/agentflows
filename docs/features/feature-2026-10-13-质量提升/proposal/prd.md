- 效果：仓库里没有任何实测数据。CHANGELOG 记录的 32 个版本，全部标注 `measurement: none`。2026-10-12 评测装置整线删除，目前没有可用的测量路径。

- 角色：14 个角色的边界只靠提示词约束，没有行为测试。

### 1.2 目标（可判定）
- **G1 效果可测**：在冻结的任务集上完成一次 A/B 实验（装插件一臂，裸宿主一臂），按事先写定的判据给出结论。结论可以是「有提升」「无提升」「无定论」，三者都合法；但必须附原始数据与判据。
- **G2 门禁可信**：门禁的每个检查项都经变异测试证明会失败；`validate.py` 拆分后单模块不超过 600 行；lint 与类型检查进入门禁；CI 在真实 runner 上连续两次通过。
- **G3 运行态同步**：`validate.py installed` 退出码为 0。
- **G4 文档可核**：文档中的计数由脚本输出并由门禁比对；入口文档收敛为一份「现状」页加若干专题页；每条「已验证」都指向可复跑的命令与输出。
- **G5 角色行为可测**：每个角色至少两个「必须拒绝」场景，并留有通过记录。

## 二、产品定位与核心原则
agentflow 是面向宿主（Claude Code、ZCode、Codex）的多角色开发工作流插件。它的核心主张是「门禁是确定性程序，而非文字约定」。本批要证明这条主张，并让门禁本身可信。

| 原则 | 说明 |
| --- | --- |
| 先测后改 | 影响效果的改动（例如合并角色）必须等 G1 的结论。工程质量改动不必等 |
| 门护门 | 门禁的任何改动需要独立评审，作者不验收自己的改动 |
| 判据先于数据 | A/B 的判据在实验开始前写入 `spec/qa`，跑完后不得修改 |
| 无定论也是结果 | 实验结果不利时，不得改写为有利。原始数据全部保留 |
| 历史只追加 | 历史记录不改写。更正另起条目 |
