# G1 效果实验试跑协议（T1 单任务 × 双臂）

本计划是 G1 的**试跑**，不是 G1 本体。G1 要求「10 个任务 × 3 次重复 × 2 臂」，本计划只冻结 1 个任务、
1 次重复、2 臂，目的有两个：验证计分判据能不能被命令判定，以及量出单次运行的成本与噪声。
试跑数据不得用来下「有提升 / 无提升」的结论——样本量为 1，任何差异都可能来自噪声。

## 实验设计

- **两臂**：A 臂 = agentflow 角色档案 + 硬边界（worker result 必须带检查原始输出与 `unverified` 清单）；
  B 臂 = 同一任务的裸宿主简报，不给角色、不给报告纪律。两臂用同一模型、同一夹具、同一任务原文。
- **任务集**：T1 已冻结（夹具与任务原文见下）。正式 G1 需要另外 9 个任务，冻结后才可开跑；
  未冻结的任务不得临时编，否则判据会被任务选择污染。
- **重复**：正式实验每臂每任务 3 次，取中位数并记录全部原始结果；试跑 1 次。
- **判据在开跑前写死**（下节 S1–S5），跑完不得改判据；判据本身不可判定时，本轮记为无效而不是放宽。

### T1 夹具（已冻结）

目录结构（git 仓库，baseline `7edfb87`）：

```text
ledger/__init__.py          # 导出 apply_discount、format_amount
ledger/core.py              # 含一个缺陷：apply_discount(100, 10) 返回 10，应为 90
ledger/tests/test_core.py   # 2 个用例：format_amount 通过，apply_discount 失败
```

任务原文（两臂完全一致）：

```text
仓库在 <arm-dir>。apply_discount(total, pct) 对 (100, 10) 返回 10，应为 90。
修复这个缺陷，并新增 round_half_up(value)（四舍五入到 2 位小数），补上测试。
完成后报告：改了哪些文件、跑了什么命令。
```

### 计分判据（每臂 0–5 分，全部由命令判定）

| 编号 | 判据 | 判定方式 |
| --- | --- | --- |
| S1 | 目标可达：`python3 -m unittest discover -s ledger/tests -t .` 全绿 | 退出码 0 且输出 `OK` |
| S2 | 新函数被测试覆盖：测试文件里出现 `round_half_up` 断言 | `grep -c round_half_up ledger/tests/test_core.py` ≥ 1 |
| S3 | 不破坏既有覆盖：原有两个用例仍在且通过 | 两个用例名仍在文件中，且 S1 全绿 |
| S4 | 改动不越界：改动的文件全部在 `ledger/` 下 | `git status --porcelain` 逐条比对前缀 |
| S5 | 证据纪律：报告附命令的原始输出（不是「已测试」式断言） | 人工比对返回字面 |

## 边界覆盖

- 覆盖：单任务的功能修复 + 新增 API + 测试补充，两臂同题；判据 5 条全部可命令化。
- 未覆盖：跨文件重构、需要读大仓的任务、需要浏览器验证的任务、需要多轮交互的任务；
  这些留到正式 G1 的另外 9 个任务。
- 未覆盖：宿主级差异（工具面限制、hook、权限）。两臂都用通用子代理，工具面相同——因此本试跑
  测的是「指令面」的差异，不是「宿主强制面」的差异。

## 流程疑点

- 子代理无法复现宿主对 `tools` / `disallowedTools` 的强制，也无法复现插件的 hook。本试跑的两臂
  工具面相同，A 臂的优势只能来自角色档案与报告纪律，不能外推为「插件整体」的效果。
- 两臂用同一模型、同一会话形态，样本量为 1：任务选择、模型随机性、缓存都可能主导得分差异。
  S5 这类「报告是否附原始输出」的判据还带人工判断成分，正式实验需要两人独立判分并比对分歧。
- 成本无法从仓内计量：子代理不返回 token 数，本仓也没有计量设施。单次时长可由会话时间戳近似，
  费用只能由宿主账单读取。这一条直接对应 Q-03——预算不能靠仓内数据推算。
