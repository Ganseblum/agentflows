# Q-03 实验预算分析

> 状态：待用户拍板。关联：`docs/PENDING-DECISIONS.md` 第 8 条①；`proposal/prd.md` Q-03。

## 一、现状

- 配置键 `EXPERIMENT_BUDGET_RUNS` 默认 0，即拒绝启动任何实验运行。
- G1 需要约 60 次完整运行（10 个任务 × 3 次 × 2 臂）。
- 预算上限未确认前，不发起任何实验运行。

**口径更正（2026-10-19 核查）**：这个键目前只写在**设计与规格**里（`spec/be/backend.md` §3 与 §5 的
M-F、`design/be/backend.md` 的配置表），**代码尚未实现**——`tools/lab/experiment.py` 不存在，
`spec/be/backend.md` §3 明写「未决前，M-F 只交付判据、接口与记录格式，不写执行代码」。因此
「保持默认 0」不是一个真实可拨的开关：今天根本不存在会启动运行的入口。措辞上应把选项 C 读作
「不实现 M-F、不启动实验」，而不是「把值保持在 0」。

## 二、问题

G1 的 A/B 实验需要约 60 次运行。每次运行需要：
- 宿主（Claude Code / ZCode / Codex）调用
- 模型推理（可能产生费用）
- 任务执行（时间成本）

预算上限需要用户确认。

## 三、选项

### 选项 A：接受 60 次运行

确认 `EXPERIMENT_BUDGET_RUNS = 60`，启动 G1 实验。

**收益**：可做 G1 实验，获取实测数据。
**风险**：有模型调用费用（具体金额取决于宿主与模型）；需要时间执行 60 次运行。

### 选项 B：调整运行次数

减少运行次数（如 30 次、20 次），或调整任务数/重复次数/臂数。

**收益**：降低费用与时间成本。
**风险**：运行次数减少可能影响结论的统计显著性。

### 选项 C：不启动

不实现 M-F 的执行代码，本轮不启动任何实验运行（不是「把 `EXPERIMENT_BUDGET_RUNS` 保持 0」——
那个开关还不存在，见口径更正）。

**收益**：无花费；无时间成本。
**风险**：无法做 G1 实验；无实测数据。若要一个可交付的 G1 结论，请与 Q-01 的选项 D（小样本人工
A/B 出「无定论」）联读——它不消耗这 60 次预算，也不依赖 M-F。

## 四、费用估算

具体费用取决于：
- 宿主（Claude Code / ZCode / Codex）
- 模型（不同模型价格不同）
- 每次运行的 token 消耗
- 运行时长

仓内没有任何计量数据，因此这里给不出金额——只能给结构：一次运行＝一次宿主任务会话（一个简报、
一次实现或一次评审），60 次即 60 个这类会话。要把金额说准，唯一可行的做法是先跑 1–2 次并记录
token 与时长，再乘 60。

另有一条既有的宿主风险必须先看：`docs/host-platform-facts.md` 的 C10 记录了三类失败——网关
502（2026-09-14 两次）、调用挂起超过 180 秒（2026-09-19 多次，`TimeoutExpired`、退出码 124）、
本机只配置了单一端点且无备选。60 次运行里只要有一批撞上这种信号，结论就会带大量「未知」，
而「未知」按仓内纪律既不算完成也不算未通过。这不是预算问题，是可行性问题。

建议：先做 1–2 次试跑，同时记录**单次费用、时长与失败率**；失败率不为零时，先把预算问题降级，
改为处理端点（U-01）。

## 五、建议

- 先试跑 1–2 次，拿到单次费用、时长与**失败率**三个数，再谈 60 次。失败率不为零（C10 已出现过）时，
  先修端点，不要拿预算去买一堆「未知」。
- 如果 G1 需要「有提升 / 无提升」的强判定：选 A 或 B，并把 Q-01 的 M-F 实现一并授权。
- 如果 G1 只需一个可交付结论：走 Q-01 的选项 D（小样本人工 A/B → 可能「无定论」），本问的 60 次
  预算就不必开。
- 无论选哪个，都需要用户书面确认运行次数与花费上限（或明确"不设上限、按试跑实测控制"）。

## 六、决策点

| 决策点 | 选项 | 影响 |
| --- | --- | --- |
| 运行次数 | 60 / 调整 / 0 | 费用、时间、统计显著性 |
| 是否先试跑 | 先试跑再决定 / 直接决定 | 预算准确性 |
