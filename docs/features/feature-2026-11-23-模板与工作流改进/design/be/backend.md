# 技术设计：安全生成和可复核评审

规格见[验收规格](../../spec/qa/acceptance.md)。本批覆盖本地文件、Git 和工具证据，数据持久化沿用现有 Markdown、快照和 JSON，无新数据库。

| 模块 | 交接和兼容 |
| --- | --- |
| 打包与发布 | 准备同父目录暂存包。源码清单与包内规则核对通过后切换。发布显式检查已暂存内容或已准备好的提交。 |
| 改动范围 | 工作区、Git 暂存区分开绑定。旧封存若缺暂存基线，返回重封存诊断。忽略文件的链接记录本身，不读取指向的文件内容。 |
| 评审简报 | 文档评审绑定已冻结文件和阶段，实施评审绑定真实任务闭包。增量还需基线与上一轮处置。快照保存来源，迁移用显式旧仓映射。 |
| 测试与缺陷 | 原生报告区分本轮执行和缓存。缺陷立案按评审轮次和 finding ID 稳定关联，产物字段按公开格式生成。 |
| 模板 | 内部方法指针用可分发入口，目标仓内链接随已生成轨道存在。审批和执行用独立状态，未决项保留责任与关闭条件。 |

| 失败情境 | 停止或响应 | 恢复 |
| --- | --- | --- |
| 已有普通目录或打包失败 | 停止切换，保全现有目录和最后有效包 | 修复输入并重建，核对原有效包 |
| 暂存区越界或封存格式旧 | 输出真实路径或重封存诊断 | 恢复合法范围，重封存并运行验收 |
| 评审对象错绑、缺依赖或同名输出已存在 | 拒绝生成可派发结果，保持源数据 | 补实际对象和依赖，选择新证据路径 |
| 报告来自缓存、UI 环境未准备 | 保留未运行或复用证据 | 按确认的路线重新执行目标测试 |
| 旧宿主无法升级或无法开启新会话 | 分开记录载荷和会话状态 | 用可用安装入口校验载荷，再实测新会话 |

集成顺序为工具接口与约定、模板生成与角色消费者、重新构建、验收及本地宿主核验。回退以旧版本的完整插件包为恢复点，已有项目文档、配置和历史证据原样保留；新工具依赖的新封存应重新生成。
