## 2. 工程基线状态

```mermaid
stateDiagram-v2
    [*] --> Missing: 目标仓未接入
    Missing --> Registered: 目标仓已有工程规范（登记入口路径）
    Missing --> Landed: 无既有规范（用模板落最小基线）
    Registered --> Stale: 规范被改但接入小节未刷新
    Landed --> Stale: 技术栈/命令/目录变更未回写
    Stale --> Registered: 复核并刷新入口或内容
    Registered --> [*]: 接入完成
    Landed --> [*]: 接入完成
```

**不变式**：`Missing` 状态下不得以「按通用默认」开始实现；`Stale` 状态下实现前必须先复核，
复核不了的条目标为缺口上报，不沿用旧值。

## 3. 主流程

```mermaid
flowchart TD
    A[Init 第 1 步：与用户确认] --> B{目标仓已有工程规范?}
    B -->|有| C[登记规范入口路径]
    B -->|没有| D[用工程基线模板落最小基线]
    C --> E[写进接入小节：工程基线入口]
    D --> E
    E --> F[工程师实现前读基线]
    F --> G{基线与任务事实冲突或缺失?}
    G -->|冲突| H[停下确认，以目标仓为准并登记例外]
    G -->|缺失| I[按缺口上报，不按通用默认推断]
    G -->|一致| J[按基线实现并跑门]
```

## 4. 失败分支时序

```mermaid
sequenceDiagram
    participant S as 任务指派角色
    participant W as 实现角色
    participant R as 目标仓工程基线
    participant G as 质量门
    S->>W: 简报（write_scope + design_refs + 基线入口）
    W->>R: 读取基线
    alt 基线存在且覆盖任务所需事实
        R-->>W: 目录/命名/测试栈/门顺序
        W->>G: 实现后跑目标仓门
        G-->>W: 原始输出
        W-->>S: 结果 + 证据（含门输出）
    else 基线缺失或条目过期
        R-->>W: 缺目录约定 / 缺测试命令 / 缺配置口径
        W-->>S: requires 调度：列出缺口与最小所需输入
        S->>S: 向用户确认或补基线，不自行编造
    else 基线与设计/代码冲突
        R-->>W: 与 design_refs 或既有实现矛盾
        W-->>S: requires design：冲突点 + 两方出处
        S->>S: 由用户裁决以谁为准后再继续
    end
```

## 5. 字段级契约

本批不新增对外接口；下列契约约束模板与 Init 小节的必需字段（验收入口是同名证据文件）。

| 契约项 | 请求字段 | 响应字段 | 失败行为 |
| --- | --- | --- | --- |
| 工程基线模板（C01） | 十个固定小节（0–9）标题与 `<填>` 占位 | 目标仓的工程基线文件 | 缺小节 → 人工评审判不合格；本批不新增机器门 |
| Init 小节的基线入口（C02） | 「工程基线入口：<路径>」一行 | 接入小节正文 | 缺该行 → 接入不完整；由任务指派角色在派发前核对 |
| 配置项表（C03） | 12 列：键/代码字段、业务作用、类型与单位、默认与来源、必填条件、合法取值、可见性、覆盖顺序、生效与生命周期、失败行为、部署映射、验证 | `design/be` §1.3.3 表行 | 缺列、空填或把前端提示当服务端校验 → Design 评审退回 |
| 边界表（C04） | 7 列：限制项、适用对象、单位、上下界、特殊值、超限结果、权威来源 | `design/be` §1.3.3 第二张表 | 只写「有上限」不写对象/单位/超限结果 → 退回 |
| 字段与数据核对（C05） | 8 类核对项 × 结论（已覆盖/缺口/不适用+理由）× 载体 | `design/be` §1.3.5 表行 | 空表或全「已覆盖」无载体 → 退回 |
| 原型自检（C06） | P1–P5 五项，逐项勾选 | `prototype/README.md` 的交付前自检 | 无勾选或无证据 → 人工评审退回；插件不代验 |
| 计划覆盖方向（C07） | 11 个方向（原 8 + 并发与竞态、生命周期与清理、契约与兼容） | `testing/plan.md` 的覆盖方向自检表 | 缺行或空白 → 计划形态不合格 |
