## 3. 环境预检

- 解释器：本机 `python3` 为 CLT 3.9.6，不足以运行 `tools/lab/`（要求 ≥3.10）；本批所有命令用
  `python3.12`。这是必须随证据记录的边界，3.9 的报错不算门失败。
- lint 依赖：若 `.venv` 不存在，`validate.py lint` 可能因缺 `ruff`/`mypy` 失败；按「未运行」记录，
  不冒充通过。若失败，先按 `README.md` 的一行就绪命令建 `.venv` 再重跑。
- 生成树：先跑 `python3.12 packaging/build_runtime.py`，再跑全量门；顺序颠倒会被新鲜度检查抓住。

## 4. 失败分流

| 观察 | 分类 | 动作 |
| --- | --- | --- |
| `doc_chain.py` 对本批红 | 链缺陷 | 修批次文档，不改 linter |
| `validate.py docs` 红 | 文档面漂移 | 按报错逐条修；版本散文问题改回「见 manifest 与 CHANGELOG」的指针写法 |
| `validate.py manifests` 红 | 版本不一致 | 五份 manifest 同步升版后重建生成树 |
| `validate.py tests` 红 | 回归 | 先确认是否为本次改动引入；必要时在父提交复跑对照 |
| 证据文件缺失 | 记录缺陷 | 补跑命令并保存原始输出，不手写结论 |
