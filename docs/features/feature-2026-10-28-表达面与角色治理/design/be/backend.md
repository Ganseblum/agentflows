## 2. 载体分层模型

```mermaid
flowchart TD
    subgraph 宿主全局["宿主全局（目标仓不可见）"]
        G[global-rules.md 托管块<br/>必须自带全文]
    end
    subgraph 插件面["插件面（随 skill 加载）"]
        S[SKILL.md<br/>入口：摘要 + 指针]
        C[contracts.md<br/>权威：硬边界全文]
        R[references/*.md<br/>分主题权威]
    end
    G -.->|同一规则，措辞可不同<br/>但动作必须等价| C
    S -->|指针| C
    S -->|指针| R
    C -->|判据细则移交| R
```

**关键不变式**：`G → C` 这条是虚线，表示**两个独立权威**而非副本——它们服务不同加载场景，
允许措辞不同，但**动作必须等价**。等价的判据是 G1-AC-01/02（锚点在场 + 指针可解析），
不是逐字相同。

## 3. 为什么不能一刀切：三个加载场景

```mermaid
sequenceDiagram
    participant U as 用户
    participant H as 宿主
    participant S as SKILL
    participant C as contracts.md
    participant G as 全局托管块
    U->>H: 打开任意目标仓的新会话
    alt 只加载了宿主全局
        H->>G: 注入 ~/.zcode/AGENTS.md
        G-->>H: 分支纪律/推送授权必须此刻可执行
    else 调用了 agentflow skill
        H->>S: 加载 SKILL
        S->>C: 需要硬边界全文
        C-->>S: 权威条款
    else 都没加载
        H-->>U: 无规则在场（本仓不承诺覆盖）
    end
```

这条时序说明：**全局块与 contracts 是两个不同的失败域**。把全局块改成指针，等于让
「只加载了全局块的会话」失去规则；把 contracts 改成指针，等于让「读了 SKILL 但没读
references 的会话」失去硬边界。所以两者都必须自足，重复是**结构性必要**的。

真正可删的是**第三份**——`SKILL.md:131`。它与 `contracts.md` 在同一加载链路里，
且读者读到第 131 行时已经能跳转。

## 4. 拆分后 `document-chain.md` 的阅读路径

```mermaid
stateDiagram-v2
    [*] --> 判断档位
    判断档位 --> 轻量档: 六条判据全为是
    判断档位 --> 完整档: 任一否/未知
    轻量档 --> 看速查表
    完整档 --> 读链契约
    读链契约 --> 产出文档
    产出文档 --> 跑linter
    跑linter --> 红: 有 finding
    红 --> 查判据细则: 改门者
    红 --> 改文档: 作者
    查判据细则 --> 跑linter
    改文档 --> 跑linter
    跑linter --> 绿: 0 finding
    绿 --> [*]
```

读者分流是这次拆分的依据：**作者只需要契约，改门者才需要判据**。

## 5. 字段级契约（载体归属表的结构）

归属表本身是本批的机器可核产物，其字段口径如下（供 G1-AC-01 的脚本读取）。

| 接口 | 请求字段 | 响应字段 | 失败行为 |
| --- | --- | --- | --- |
| 载体归属表行（规则/权威/自足/指针/处置） | `规则名`、`权威载体路径`、`自足载体路径`、`指针载体路径`、`锚点字符串` | 该行五列非空；权威路径存在；锚点在权威文件中命中 | 路径不存在或锚点未命中 → 脚本判红并打印该行 |
| 拆分标题对照（原/新） | 原文件 `##` 标题集合、新文件 `##` 标题集合 | 双向差集为空 | 差集非空 → 打印缺失标题清单 |
| FE/BE 裁决记录（三条件实测） | `不一致例数`、`分歧项数`、`合并稿行数` | 三个数值 + 「已裁决：合并/保持分立」 | 任一数值缺失 → 判「数据不足」并写明缺哪例 |
