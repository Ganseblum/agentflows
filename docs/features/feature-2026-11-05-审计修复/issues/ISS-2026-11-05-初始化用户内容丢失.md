## 现象

来源为审计 G01，任务 RECORD-INIT-G01。初始化后在 Cursor、Claude 入口托管区段前后加入用户附录，再次初始化；预期只更新自有区段，实际整文件重写使用户内容消失。普通 AGENTS 原始尾空白及旧 Claude 附录也未保全，构成 P1 用户内容损失。当前没有单独的用户复验反馈；观察依据为审计复现与回归。
本记录以本仓源码为证据地址：`agentflows@511b9ef7b66a4b23cb859345d1810981aa083f5b:skills/agentflow/scripts/init_workspace.py`。以下为旧版 RED 日志逐字摘录，原始定位见回归节。
```text
FAIL E1-sentinels-and-CRLF: .cursor/rules/agentflow.mdc: prefix changed
FAIL E1-plain-prefix: plain AGENTS bytes changed
FAIL E1-legacy-claude: legacy appendix changed
2/14 passed
exit=1
```
14 项定向检查原为 2 pass / 12 fail；该总数还含 symlink、冲突等其它审计问题，不能把全部失败归入 G01。

## 根因

Supervisor 已确认的代码归因：旧 Init 对 Cursor 和 Claude 采用整文件替换，却对外承诺保留托管块外内容；入口所有权边界在实现中被扩大到整文件。普通入口追加及旧 Claude 迁移同样没有守住原始字节保全。旧自测仅覆盖 AGENTS 块外内容和普通幂等，未验证 Cursor/Claude 用户附录。故为 Agentflow 自身产品代码的逻辑错误，不归因为宿主加载问题。
上述基线地址对应的 RED 原句“frontmatter + 标记块整体重渲染（该文件整体为生成物）”揭示了错误边界；修复对应 `本轮已审快照 snapshots-tools/snapshot-2/skills/agentflow/scripts/init_workspace.py` 与 `本轮已审快照 snapshots-tools/snapshot-2/skills/agentflow/scripts/workflow_lib/managed.py`，该 revision 明确指未提交源码快照，不冒充 Git commit。

- M2 断言与实现同源：本 G01 未证实，不据此归因；没有已确认的同源断言缺口。后续检查期望 bytes 是否独立来自运行前用户样本，证据层级为测试代码审查与文件字节。
- M3 跨边界不变量无 owner：本 G01 未证实，不据此归因；不把已见的覆盖错误推断为 owner 缺失。后续检查各宿主真实 Init 入口均断言“仅自有区段可变、外部 bytes 不变”，证据层级为 CLI 集成。

## 修复方案

发现阶段候选建议为统一各入口的自有区段替换、按 bytes 保留前后内容、迁移旧 Claude 时只接管归属行，并补齐多入口字节回归；主要风险是旧指针识别误接管及换行归一化。方案状态按 Supervisor 交接记为“已采纳”；审核依据为其接收的独立 REVIEW-TOOLS-041 结论，本节不构成 Recorder 新批准。实际落地另记如下。
