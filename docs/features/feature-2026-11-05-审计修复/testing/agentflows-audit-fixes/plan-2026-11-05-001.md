## 流程疑点

- Q1【已补齐验收，候选待绑定】：四卡与本次补充已明确入口/testid、状态、角色、输入与关键失败；23的异步控制、fixture启动/清零入口、定位别名实际注册处和原生报告路径由 Executor 在首跑前固定。CARD-1是file层CLI任务，不存在产品browser入口；其余三卡browser必跑。UI超时/会话/退出无此业务设计，按边界表N/A/未测，不新增需求。框架确不支持时逐项写技术原因与TODO，不能API降级关闭browser。
- Q2【候选待绑定，非正常开发阻塞】：主审已定29个原生case，Executor接收 `test_tools_regressions.py`、install-verify 及相应回归时登记真实原名→TC/G映射、绝对入口/源码快照和报告路径；允许一TC对应多个原生case，不要求改原名，不以未产报告写通过。七项既有self-test仍全跑；独审补审工具未覆盖的语义。
- Q3【执行接收职责】：真实三端安装路径、三端新会话加载证据、ZCode全局三项和真缺陷记录ID由主审/Executor供给。磁盘一致与新会话加载分别记账；Codex/Qoder若未做新会话只可声明安装已读回。draft经主审审阅后才可active；本角色不批准、不回写状态。新增文档的index.md登记由主审在自身范围同步，本角色不越界写索引。
- Q4【兼容范围待独审】：slug和样本字段长度/字符规则本次已确认，不再作为全计划阻塞；遗留manifest可接受版本及迁移行为由主审定位已支持范围，无定义的旧版不自行承诺兼容，单列未验证。明确安全不变量与缺失完整集仍按04执行，不能从候选正则/响应推答案。
- Q5【未运行与结论】：每轮逐例及变体记录pass/fail/blocked/not-run与实际证据层。目标断言违背为fail；缺预期/权限/真实依赖为blocked；未进入该轮为not-run并写阻塞什么；缺报告/未收集/runner崩溃不得计有效red。记录人工核对、指定执行满足预期、独审覆盖复核三种结论分开；结构映射不证明覆盖完整，必需验证缺失时不得complete。
