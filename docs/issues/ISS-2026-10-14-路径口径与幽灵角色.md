## 现象

2026-10-12 结构改造批四期已把批次目录迁入 `docs/features/`，但活面文本里仍有一批旧的
`features/<批次>/…` 路径在指导读者与角色：

| 位置 | 旧写法 |
| --- | --- |
| README.md 布局表 | `features/` |
| skills/agentflow/SKILL.md 自动化测试段 | `features/<批次>/testing/<项目>-<功能>/` |
| docs/system-guide.md（5 处，含图） | `features/<批次>/plan/`、`features/<批次>/testing/` |
| reviews/README.md | `features/<批次>/reviews/` |
| agents/plan-architect.md、test-planner.md、test-executor.md、reviewer.md | `features/<批次>/testing/` |

同一批改名后，`docs/project-structure.md`、`docs/product/spec/method-spec.md` 与 index.md 已经
用了 `docs/features/`——同一件事在仓里有两个口径，读者按哪份文本走都可能走错。

第二处：`execution-coordinator` 在 `SKILL.md`（规划段与恢复段）、`README.md`（成熟度段）三处
被提及，并被 `doc_chain.py` 的 `ROLE_WORD_EXEMPT_PHRASES` 判为合法词；但它不是当前角色，没有
角色档案，`AGENTS.md` 也没有它。为一个不存在的能力保留引用面，会让读者（与 agent）以为它
可以被委派。

## 根因

1. 结构改造批按「目录与索引」验收，没有对**活文本中的路径串**做机器扫描；`validate.py docs`
   检查断链与退役路径，但 `features/<批次>/testing/` 这类带占位符的模板路径不是链接，扫不到。
2. `execution-coordinator` 是设计文档里的未来角色，被顺手写进方法文本后没有标注「当前不存在」；
   也没有任何条款禁止把未实现角色写进委派简报。

## 修复

1. 上述 8 个文件的活面路径统一为 `docs/features/<批次>/…`（历史记录 episodes/ 与 docs/issues/
   里的旧路径是已发生的事实，按硬边界 8 不回改）。
2. `SKILL.md` 两处、`README.md` 一处的 `execution-coordinator` 加显式限定：该角色当前不存在，
   不得作为委派对象、产物落点或任务归属写进任何简报；队列、租约与恢复由 Supervisor 承担。

## 回归检查

- `python3 tools/lab/validate.py docs` → PASS（断链与退役路径扫描无发现）。
- 活面 grep `features/<批次>` → 仅剩本记录的引文与历史记录；`docs/features/` 为唯一口径。
- `python3 tools/lab/validate.py all` → 9×PASS；`unittest` → 60 OK。
- `doc_chain.py --self-test` 仍 46/46（Execution Coordinator 的豁免短语保留，它仍是规划中的
  角色名，只是不得被当作可用能力）。

## 怎么避免

改目录结构时，同批扫一遍活文本里的路径串（`grep -rn 'features/' --include='*.md'`，排除记录
面），而不只改链接与索引；未来角色写进方法文本时必须带「当前不存在」限定，否则读者会把它当
成可委派项。

## 审查

2026-10-19 独立复审（agentflow:reviewer 子代理，只读）。修复声称核对成立：8 文件活面裸 features/<批次> 零残留；SKILL.md 两处 execution-coordinator 均带「该角色当前不存在」限定（比声称更强）；doc_chain.py:126 豁免短语保留。回归证据：validate.py docs PASS、all 9×PASS、unittest 96 OK、self-test 63/63。review_decision：approved。
