## 现象

2026-10-13 全仓审计读门的实现，发现三处「门看起来在守，实际守不住」：

1. **`validate.py protected` 只做字符串前缀比较**：它遍历 `REQUIRED_PROTECTED_PATHS`，检查
   每个必需条目是否被某条声明前缀覆盖——但从不检查声明的条目在仓库里是否真实存在。一条拼错的
   路径、一个已改名的文件、一个从未存在过的路径，同样能「覆盖」必需条目，于是清单可以保护着
   不存在的东西而每一道门保持绿色。
2. **`validate.py schemas` 只查元声明**：仅确认 `$schema` URI、`$id` 非空、`$ref` 指向的文件
   在盘；一个契约可以删掉全部 `required`、把 `additionalProperties` 放开、甚至不再是对象契约，
   仍然 PASS。而编译步骤正是用它来判定候选记录的——放宽被度量的契约就是编辑自己的门（硬边界 6）。
3. **两个决定「什么被判定」的文件不在保护面内**：`tools/lab/record_store.py`（改进环的检索与
   索引入口）与 `packaging/build_runtime.py`（决定安装面装进哪些角色与 schema）既不在
   `protected-paths.txt`，也不在 `REQUIRED_PROTECTED_PATHS`。

## 根因

1. 保护检查的实现停在「覆盖面」这个可字符串化的层面，没有把「覆盖的东西必须存在」当成判据；
   属 `missing-constraint`——没有任何条款要求清单条目在盘。
2. schema 检查写于契约刚引入时，目标是「别写坏 JSON」，从未升级为「别放宽契约」。
3. 包含规则（`protected-paths.txt` 头部注释）按「是否决定候选被度量或评判」判定，但最近两次
   新增工具（record_store 2026-10-12、build_runtime 更早）没有回头套用这条规则——规则在，套用
   没有制度化。

## 修复

1. `validate_protected_paths` 增加存在性判据：每条声明的条目必须在仓内解析到真实文件/目录，
   否则 FAIL（错误信息写明「清单不能保护一个不存在的路径」）。
2. 新增 `validate_schema_shape`：`type` 必须为 `object`、`properties` 非空、`required` 为非空
   字符串数组、`additionalProperties` 必须为 `false`、`required` 每一项必须在 `properties` 中
   声明。
3. `protected-paths.txt` 增加 `tools/lab/record_store.py` 与 `packaging/build_runtime.py`，并在
   后者旁写明包含理由（它决定安装面装什么）；`REQUIRED_PROTECTED_PATHS` 同步两项。

## 回归检查

一次性副本（`/tmp/af-mut`）上的三个变体，退出码与逐字输出：

```

变体2 tools/lab/trend.py → tools/lab/trend-typo.py（前缀仍「覆盖」，修订前抓不到）→
FAIL protected (2 error(s))
  - .../protected-paths.txt: required gate path 'tools/lab/trend.py' is no longer covered by any declared prefix
  - .../protected-paths.txt: declared protected path 'tools/lab/trend-typo.py' does not exist in this repository — the gate surface cannot protect a path that is not there

变体3 删掉 schemas/plan.schema.json 的 required（修订前抓不到）→
FAIL schemas (1 error(s))
  - schemas/plan.schema.json: must declare a non-empty required list of property names
```

- 真实树：`python3 tools/lab/validate.py all` → 9×PASS；`unittest` → 60 OK。
- 故障注入一律在 `/tmp` 副本执行（AGENTS.md 实验与恢复规则）。

## 怎么避免

门的价值不在「检查了多少项」，在「最弱那一项能否被绕过」。每加一个检查项，同批给出它的绕过
变体并在副本上跑出红灯——没有负向证据的检查项记为未验证。
