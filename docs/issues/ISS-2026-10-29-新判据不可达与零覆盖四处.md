## 现象

预期：新写的每条判据都应「在门路径上可达、对目标形态判红、且被可复跑的夹具钉住」。
实际四处不成立（全部由 2026-10-29 两路独立评审先提出，主侧随后在 `/tmp` 副本复现）：

1. **不可达**：伪降级判定接在 `validate_review_markdown` 的 schema 早退之后，而 `allOf` 吃的是
   同一个形态——Python 层永不调用，门输出是不点名记录的 `  - $: missing required property 'dispatch_errors'`。
2. **漏判**：episode 指针判据要求整个字段值成路径形状（`fullmatch`），「`A；B；C`」式取值整体跳过；
   `/tmp` 绝对路径静默放过。判据上线后 `PASS artifacts` 与「记录里一条没少」同时为真。
3. **零覆盖**：`validate_carrier_map` 没有任何用例；设计点名的 `GC-01…03` 夹具根本没写。
4. **夹具无判别力**：`C18-04`、`C18-07` 两行的状态文本不含任何开放词，删掉「已确认豁免」与
   「表头须有状态列」两条护栏后两例仍为 0——而 `selftest.py` 注释宣称它们钉住这两条护栏。

反证原文（`/tmp` 副本，逐字）：删调用点 → `Ran 7 tests in 0.002s / OK`（应 FAIL）；
判据收窄前失效命中 0 条、收窄后同一份记录树命中 116 条（31 份记录）。

## 根因

`error_kind: logic-error`。四条同属一个成因：**判据被写成函数与文档条款，而「它会不会真的被执行」
不是任何一条断言的对象**。同一形态本仓已两次记录——
`docs/issues/ISS-2026-10-23-新判据声明了却不被校验的六处.md`（声明了不校验）与
2026-10-26 审核 G13（负例钉不住目标判据）。本轮新增判据时在「先夹具后实现」的自述下仍然漏掉，
说明缺的不是流程文字，而是**接线级断言这一固定形态本身**：本轮由评审补出「patch 被调用函数、
断言门路径真调用它」这类用例后才可复跑。

## 修复方案

- 挪到 schema 早退之前，并让接线用例只认 Python 层独有的措辞（已采纳）
- 值内逐路径判定 + 绝对临时路径判红 + 与散文侧/C23 同口径（`is_file()`、`N/A[:：]`）（已采纳）
- 补归属表四条用例，其中一条专钉接线（已采纳）
- 两条无判别力夹具改成真实形态，删护栏即转红（已采纳）
- 防再犯候选：把「新判据必须有一条门路径级（接线）用例」写成 `AGENTS.md` 硬判据（**待审核**，
  属条款变更，登记 `docs/PENDING-DECISIONS.md` 不在本记录自行落地）

## 修复

`tools/lab/gate/records.py`（判定顺序、逐路径、字段名进 message、删重复调用）、
