## 现象

评测整改批（0.20.0）在实现后做同步核查，发现四处自述与实现面不一致：

1. `pre-push.sh` 与 `validate.py` 已支持仓内 `.venv` 探测，但 `publish.sh`、`upgrade-zcode.sh`、
   `upgrade-codex.sh` 三个脚本仍只有 `AGENTFLOW_LINT_PYTHON` 一条路径——**正是本批在批评的
   「同一规则多处维护、改一处漏三处」**。三个脚本合计仍在用 `LINT_PYTHON="...:-python3"`。
2. `index.md` 的「查本仓自评」仍指向 2026-10-26 审核，未指向本批的 2026-10-28 评测报告；
   批次索引节缺本批条目（违反 AGENTS.md「新增文档必须同步维护 index.md」）。
3. `docs/evaluations/README.md` 的收存清单缺 `AGENTFLOW-EVAL-2026-10-28.md`。
4. `docs/features/README.md` 的在途批次表缺本批。
5. `docs/releases/pending-test.md` 未登记 0.20.0 的待验收项（0.20.0 未发布、未重装）。

## 根因

本批改动的实施顺序是「先改契约 → 再改预检脚本（pre-push）」，
`.venv` 探测只落在 pre-push 一处，另外三个消费 lint 的脚本未同步；
索引类文件（index / 两个 README / pending-test）属于「新增文档必须同步维护」的纪律范围，
实施时未把它们纳入同一变更。归因为 workflow_policy：不是某条判据缺失，而是
「同一机制的所有消费点」没有在改动时被枚举。

## 修复

- 三个脚本的解释器选择改为与 pre-push 相同的优先级（显式 env > `.venv` > `python3`），
  `bash -n` 语法检查通过。
- `index.md` 自评指针改指 2026-10-28 评测报告；批次索引节补本批条目。
- `docs/evaluations/README.md` 收存清单补本报告行。
- `docs/features/README.md` 在途批次表补本批。
- `docs/releases/pending-test.md` 补第 6 行，四项待验收全部标「未做」，不记为已验收。

## 回归检查

- `python3.12 tools/lab/validate.py all` → 11/11 PASS（EXIT=0）。
- `python3.12 tools/lab/validate.py docs` 覆盖 index/README 断链与退役路径扫描，PASS。
- `bash -n` 三个脚本全部通过。
- 未新增门判据（本问题是「在场」类，不是「判据缺失」类），故无变异实验。

## 怎么避免

改动一个机制时枚举它的**全部消费点**再动手：`.venv` 探测的消费点是四个脚本加 validate.py；
索引同步的消费点是 index.md、两个 README 与 pending-test。本批同时把这条要求写成
`docs/features/README.md` 纪律节的一句可执行表述（新增批次必须同日更新四处索引）。
