## 现象

同一个「归档」口径在本仓有四份文字，其中三处互相打架：

1. **执法点写错**。`docs/issues/README.md` 的归档规则节原写：

   > 「归档规则」节的规则由 `tools/lab/gate/records.py` 的 `validate_bug_layout` 强制，已在 2026-10-26
   > `/tmp` 副本演练确认：根目录留 `rejected` → FAIL、移入 `归档/<date>/` → PASS

   实测把状态与位置的耦合定位在 [`tools/lab/gate/workspace.py`](../../tools/lab/gate/workspace.py)
   （`:159-167`），`validate_bug_layout` 只管文件名形状、`bug_id` = 文件名 stem、日期目录 =
   `recorded_at` 日期与 id 唯一。归属写错一处，下一个人按函数名去找判据就会找不到，并可能据此
   以为「换个函数就没有这条」。

2. **两份接入模板教了相反的规则**。`skills/agentflow/templates/hub/issues-README.md` 与
   `skills/agentflow/templates/hub/index.md` 都写「关闭或被拒条目移入 `归档/<日期>/`」。照模板做的
   目标仓会把 `verified` 记录搬进归档，而这在本仓的门上是直接判红的一条：

   ```text
   $ python3 tools/lab/validate.py artifacts      # 副本内：把一条 verified 记录移入 docs/issues/归档/2026-09-14/
   FAIL artifacts (1 error(s))
     - .../docs/issues/归档/2026-09-14/ISS-2026-09-14-claude-json-schema-被拒.md: only rejected records may be archived; verified records stay in place
   ```

   模板是本仓交付给目标仓的下限，与本仓的门相反即是缺陷，不是风格差异。

3. **一处虚假类比**。`episodes/README.md` 原写 episode 归档「采用与 `docs/issues/归档/` 一致的口径」，
   但前者按月下沉、与记录状态无关，后者只覆盖 `rejected`。两者同名不同义，"一致"这句会把人引向
   把 issue 的规则套到 episode 上（或反之）。

4. **本轮我自己又复述了一次错归属**（CHANGELOG 0.25.0 节的「未做的两项」把上面第 1 点原样抄了一遍，
   还追加了一句「要改受保护的 schema，属门变更需显式评审」——`schemas/bug-record.schema.json` 里那句
   只是 `description` 散文，不构成约束，搬 `verified` 也不需要改任何门）。

## 根因

`error_kind: ai-ignored-doc` + `attribution: workflow_policy`。三件事同一个成因：

- **规则写在多处，没有指定单点**。同一结论在 README、模板、episodes README、schema 描述、评审快照里
  各写一遍，改门代码时不会有任何机械信号提示"这些散文该跟着改"，于是第一轮就漂移了（归属写错），
  第二轮把错的继续抄下去（模板与 CHANGELOG）。这正是本仓反复记录的形态——同类前案见
  `ISS-2026-10-23-新判据声明了却不被校验的六处.md` 与 `ISS-2026-10-28-整改批自述与实现面不同步.md`。
- **模板没有和门做过对照**。模板是给目标仓的下限，但它本身从不被这些门校验（C27 只管阶段文档与模板
  的相似度，不管模板的口径是否与门一致），所以「模板教反规则」这类缺陷没有任何检查覆盖——
  与 `unverified-behavior-claims` 类同型：写的时候没人问「这条会不会与执行面矛盾」。
- **我的复述未经实测**。上一轮我引用 README 的归属而没有去读代码，`grep` 到 `validate_bug_layout`
  的 docstring 里那句「Archived (rejected) records keep a date directory」就当成了强制点；
  真去跑一次副本演练只花几分钟，代价却记进了发布记录。

## 修复方案

作为建议记录，未视为已批准：把「模板口径是否与门一致」纳入一条可运行的对照检查（例如让
`validate.py docs` 或文档链 linter 对 `templates/hub/*` 里的记录面口径做一次断言），避免下次再靠人读。
本轮未实施——它需要新增判据与夹具，属门变更。

## 修复

已落地（本轮）：

- 定义收拢到 `docs/issues/README.md` 的「归档规则（本仓单点定义，别处只引用本节）」一节：只有
  `rejected` 进 `归档/<recorded_at 日期>/`；`verified` / `fixed-pending-review` / `open` 原地保留，
  并写明不搬的理由（记录 id 即文件名，复发台账与评审记录按路径引用）；执法点分两处（状态↔位置在
  `workspace.py`，形状与 id 在 `validate_bug_layout`）；附两例判据的逐字消息与可复现命令。
- 同节增加本仓「归档」一词的四义对照，并声明 `reviews/agentflow-关闭证据门/archive/2026-10-28-001/`
  内快照沿用旧归属、作为当轮逐字快照原样保留、现行口径以该节为准。
- `skills/agentflow/templates/hub/issues-README.md` 与 `templates/hub/index.md`：「关闭或被拒条目移入归档」
  改为「只有被拒（`rejected`）条目移入归档，已验证记录原地保留」；看板表头由「编号 / 标题 / 状态 / 归属」
  改为 `AGENTS.md` 规定的台账四列「编号 / 一句话 / 记录链接 / 归属」，去掉与 C15 打架的行内状态列。
- `episodes/README.md`：「采用与 `docs/issues/归档/` 一致的口径」改为「与 `docs/issues/归档/` 不同义，
  别互相套用」，并指向定义单点。
- `CHANGELOG.md`：0.25.0 节的错误归属就地附勘误；本记录登记本轮。
