## 现象

在目标仓 test-login 上，以「实现一个登录功能」的措辞发起的一次运行（2026-10-10，宿主加载
0.10.0 快照）产出了与用户预期不符的交付：

- 落点自创：产物是单文件 `test-login@5097938:records/plans/login_feature.md`（`records/plans/`），
  而不是链契约「目录布局」里的两种形态之一（文档枢纽仓 `<project>-workflow-ai` 或普通业务仓
  `docs/features/`）。
- 未触发提问：范围由运行自行填写（记录里「明确不做：注册 / 找回密码…」），用户期望的产品问题
  （邮箱绑定、手机号验证、校验机制、短信验证码防抖 / 节流）一个未问。
- 质量门缺席：单文件产物无 mermaid 图、无角色目录结构；`doc_chain.py --file` 只查文本形态
  （当时 PASS），结构 / 质量检查（C1–C11）只作用于链目录，整条链未建立。

外部产物节录（地址 `test-login@5097938:records/plans/login_feature.md`；以下两处引用原文，仅去行首标记）：

> 明确不做：注册 / 找回密码 / 改密、多实例会话存储、HTTPS / 限速 / 审计（见 §3 残余风险）、路由与鉴权守卫、`href="#"` 死链与 Google 外链图标的清理（范围外）。
>
> | 用途 | 后端实现任务与前端实现任务的**冻结契约**（§2）与集成验收依据（§6） |

## 根因

两条约束缺口叠加：

① 触发面缺口：`SKILL.md`「文档交付链」与链契约「使用时机」只覆盖「用户要求产出文档集」与
「feature 先有文档、尚无代码」两种情形；以「实现功能」措辞进入的 feature 工作不在触发面内，
采集访谈（链契约「采集访谈」节）与落点选择（链契约「目录布局」节）随整条链一起缺席。提问纪律
（契约「先问再假设」节）存在，但没有任何一步在实施型路径上执行它。
② 落点无人定：Init 的四项确认（语言 / 术语 / 分支 / 检查命令）不含「文档与记录落点」；两种
形态没有任何人被问过、被定过，运行就地在邻近项目惯例之间自拼了 `records/plans/`。

## 修复

1. `skills/agentflow/SKILL.md`：
   - 「首次接入（Init）」由四项确认扩为五项，新增「文档与记录落点」（无既有约定时默认推荐
     文档枢纽仓 `<repo>/<name>-workflow-ai/`；两种形态二选一、不得自创第三种）；
   - 「文档交付链」触发面扩为含「在目标仓实施一个新 feature（代码工作随行）」，链序写明
     `接入 → 采集访谈 → 提案 → spec → 设计 → 计划 → 实施`；产品语义未决分支一律交用户；
     轻量降档须由用户选择并在 feature README 声明；
   - 运行工作流第 1 步加交叉引用：新 feature 先完成接入与采集访谈。
2. `skills/agentflow/references/document-chain.md`：「使用时机」同步扩触发面；「目录布局」改为
   Init 与 owner 确认、默认推荐枢纽仓、不得自创落点；模板指针改角色目录命名。
3. 典型案例验证：在 test-login 建 `test-login-workflow-ai/` 枢纽与
   `features/feature-2026-10-10-登录功能/` 全链（proposal / spec / design / plan，含时序图 /
   流程图 / 架构图、字段级契约、异常矩阵、线框与待冻结问题台账），对目录运行
   `python3 tools/lab/doc_chain.py` → PASS；`/tmp` 副本注入 `alt → opt` 破坏 → C4 被正确判
   FAIL（负向对照，副本已删除）。
4. 提示词面审计同步（本批收尾）：「首次接入」四项→五项写进 `AGENTS.md` 的「接入新项目」节；
   `agents/reviewer.md` 计划模式的计划契约指针由插件仓相对路径改为「所评审仓」表述（插件仓 /
   目标仓分别指向）；`SKILL.md` 的上下文纪律补「角色档案里的记录根与产物路径写进委派简报前
   映射为目标仓文档枢纽下的确切路径」。
