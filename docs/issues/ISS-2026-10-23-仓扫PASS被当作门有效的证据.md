## 现象

本批实现 C23 后，我在验收点与拍板口写下：

> `doc_chain.py --repo .` → `PASS decision-gate`；当前 findings 为 0

语气是「门照到活文件且都过了」。事实是：`docs/features/feature-2026-09-19-产品线完善` 三张计划的
ID 列写成反引号形式（`` `T01` ``），而当时的任务号解析用的是 `^(T\d{2,})\b`——反引号开头即不匹配，
**该批次 15 行状态行全部不可见**，所以那个 0 是「一行都没读到」。

独立评审用一条字符级修补复现（在 `/tmp` 副本里给解析加一次 `.strip("`")`）：

```text
FAIL doc-chain (6 findings)
  - C23 证据在场: PLAN-LOOP-SMOKE-001.md T01 标为已完成但证据列无可复核载体（…）
  - C23 证据在场: PLAN-LOOP-SMOKE-001.md T03 …
  - C23 证据在场: PLAN-PRODUCT-001.md T03 …
```

## 问题代码

```python
# tools/lab/doc_chain.py（修复前）
m = re.match(r"^(T\d{2,})\b", cell.get("ID", "").strip())
```

同一文件里 C9 早已有一条任务号方言常量（`TASK_ID_RE = ^(?:FT?\d{2}|T\d{1,2})$`，并做
`strip("`* ")`），新代码另起一套正则，于是两套写法各自能认一部分批次。

## 根因

**把「检查返回 0 条」当成了「检查通过」，中间那步「检查到底读到了几行」没有任何人要求补。**
具体三层：

1. 我的断言来自推演（「我实现了 C23，所以它在读」），不是最小实验——正是 `unverified-behavior-claims`
   类的第三次；同一类的前两次（ISS-2026-09-15-未验证行为断言反复出现、ISS-2026-09-21-episode信号未验证零复发断言）都以「评审未报≠没问题」收场。
2. 判据本身没有自证机制：既没有断言「读到了 N 行」，也没有要求负例覆盖方言的另一种写法；
   98 例自测全绿是因为夹具的行 ID 一律不带反引号（可计数检索：夹具与单测里反引号 ID 出现 0 次）。
3. 契约里 §6.1 写的是「一个或多个 `T\d+`」，等于允许实现只认一种写法——文档把盲区写进了判据。

## 修复

1. 任务号与列名解析单点复用 C9 的方言与归一化：`plan_task_rows` 走 `TASK_ID_RE` + `_norm_col`，
   承接表引用列走 `trace_task_ids()`；表头带 `**` 或反引号都不再让整表静默不可见。
2. 判别夹具 100（反引号 ID 必须判红）与变异项 M57（标题作用域）、M58（路径解析）钉住不回退。
3. 口径措辞改为带范围：G1-AC-05 与 `docs/PENDING-DECISIONS.md` 第 11 条都写明
   「归零的前提是 8 行历史散失证据按 `N/A: 理由 + 出处` 显式登记」，不再用「PASS」单独背书有效性。
4. 新条款：`design/qa/testing.md` §4 增 V-05「0 findings 有两种成因，必须附扫描到的对象计数」，
   并把「新增判据必配正例 + 破坏例 + 不误伤例」写成本批的自检要求。

## 审查

待独立评审第二轮在冻结 revision 上复跑：`--self-test`、三个批次目录模式、`--repo .`，
并按 `AGENTS.md` 的验收脚本纪律要求先打印命中原文再判 PASS/FAIL。

## 怎么避免

- 任何以「门 PASS」为据的结论，必须先给出**该检查读到的对象数量**或一条会让它变红的破坏实验；
  只有退出码不构成证据（本条正是 `AGENTS.md`「检查/验收脚本必须先打印命中原文再判 PASS/FAIL」的延伸）。
- 新判据禁止另立解析正则：凡与既有判据同族的语法（任务号、列名、路径）必须复用既有归一化函数，
  否则两套方言会在不同批次上给出不同的「绿」。
