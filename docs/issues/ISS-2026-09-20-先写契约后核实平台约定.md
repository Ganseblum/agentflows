## 现象

为 aiwork 定时任务 feature 写 design/be 接口契约时，直接自编了响应包裹与错误码体系：

```text
自编：{ "code": 0, "message": "ok", "data": {} } + AUTOMATION_LIMIT_EXCEEDED 等字符串码
现网：{ "errno": 0, "data": {} }；失败 { "errno": 60507, "errmsg": "…" }，HTTP 由 errcode 表唯一确定
```

现网证据（safe-agent-nexus，后核实）：

> `global/errcode.go`：errno → (HTTP 状态码, 对外文案) 的**单一事实源**……601xx/602xx/603xx/604xx 号段规则
> `global/errcode_test.go`：门禁——errno.go 里声明的每个 Errno* 常量都必须在 errorCodeTable 里登记
> `contracts/openapi/nexus-v1.yaml`：对外契约权威承载

同型既往缺陷：docs/issues/ISS-2026-09-19-office计划未验证SDK假设无spike.md（未验证 SDK 假设先写计划）。本次是其在「接口契约约定」维度的复发：执行链路的勘察做到了文件级，但响应包裹/错误号体系这类**约定类事实**没有先核实就落笔。

## 根因

document-chain.md 的 depth-first scoping 条款只约束「unread 的代码事实」："when the code facts a design needs are unread, stop before design and demand them"——没有点名**响应包裹、错误号体系、鉴权约定、既有接口惯例**这类契约约定必须先对照现网（errcode 表 / openapi / IDL）再写；design 模板也没有「契约真源」字段强制声明。

## 修复

已按上述方向整合入库（同仓提交：agents/reviewer.md、skills/agentflow/references/document-chain.md、`document-chain-templates.md`（指针文件，已于 2026-10-13 删除）），regression_status=not-run（规则文本变更，无自动化回归面）；生效仍待 improve 治理环收口（evaluator/governor/版本发布）与插件重装。

2. design 模板的 1.4 节增加「契约真源」占位字段。
