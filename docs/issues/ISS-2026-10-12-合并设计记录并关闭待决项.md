## 现象

用户「全部处理更新」——要求把此前逐批挂起的遗留项一次结清。挂起项四类：

1. 三份早期设计文档（`host-native-plugin-design.md` 106 行、`self-improvement-design.md` 109 行、`agent-product-boundary.md` 164 行，共 379 行）平铺在 `docs/` 根，读者要读三份才能拼出「产品边界 / 宿主形态 / 自迭代」全貌；且它们被 `validate.py` 的 `VERSION_PROSE_FILES` 逐个钉住——此前因脚本停手令一直未动。
2. `evals/` 的定位没有书面结论：改进环停用后它成为无消费者的存量，但 README 未标注，读者无法从文档判断它是活的还是废弃的。
3. 跨批次待拍板清单（`docs/PENDING-DECISIONS.md`）第 4 条的范围只写「本地化批与 youc 吸收批」，未纳入 2026-10-12 五批对受保护面（validator/tests/角色/规则书）的大量改动——回溯评审的范围失真。
4. 批次 README 的进度标记（design ☑）与产品链门禁（技术方案评审门 ☐）口径不一致。

## 根因

前四批以「结构优先、脚本冻结」推进，设计文档合并被守卫清单挡住而挂起；其余三项是「改动完成后未回到挂起清单复核」的收尾缺口——与本日质量批（ISS-2026-10-12-重构后内容质量清扫）同源：**批次收尾缺少「挂起项回扫」步骤**。

## 修复

1. 三份设计文档合并为 [`docs/design-decisions.md`](../design-decisions.md)：保留全部仍生效的决策、边界原则与六个自迭代边界、当前实现状态与对外口径，压缩已实施的过程细节（迁移步骤、重复表述）；`VERSION_PROSE_FILES` 由四文件收窄为 `README.md` + `docs/design-decisions.md` 两文件（守卫目的不变：成熟度散文必须指向版本事实源）。引用改指 README / index / project-structure / product 链（README、design 决策出处列）。
2. `evals/README.md` 增现时状态标注：**仪器存量**——暂无活跃消费者，恢复仪器化改进时基线现成；`measurement: none` 口径重申。
3. `PENDING-DECISIONS.md` 第 4 条范围并入 2026-10-12 五批受保护面改动（validator 多次修改、tests 重构、角色文件与规则书更新），推荐动作同步为复核该日全部改造批提交。
4. 批次 README 的 design 由 ☑ 改 ◐（成稿待评审），spec 行补评审门状态并指向 PENDING-DECISIONS 第 1 条。
