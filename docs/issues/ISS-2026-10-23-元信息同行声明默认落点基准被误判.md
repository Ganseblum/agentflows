## 现象

批次 README 的元信息习惯把多个字段写在同一行。按契约写法声明默认落点基准时，C9 报出一条假的
「目录不存在」：

```text
$ python3.12 tools/lab/doc_chain.py docs/features/feature-2026-10-22-追溯闭环与证据在场
FAIL doc-chain (4 findings)
  - C9 落点基准: README 声明的落点基准 .（主实施仓根，默认）；最后更新时间：2026-10-22 在目标仓根下不存在
```

被当成目录名的字符串包含了后半句「；最后更新时间：2026-10-22」。

## 根因

`tools/lab/doc_chain.py` 的 `LOCATION_BASE_RE = re.compile(r"落点基准[：:]\s*([^\n]+)")` 捕获到行尾，
而 `_declared_base()` 只做了一次 `｜` / `|` 分隔与末尾括号的剥离，**不按分号截断**。于是：

- `v` 变成 `.（主实施仓根，默认）；最后更新时间：2026-10-22`；
- 剥离末尾括号的正则 `[（(][^）)]*[）)]\s*$` 因为串尾不是括号而不生效；
- 于是既不是 `.`（默认值白名单）也不是「本批次目录」，走到 `repo_root / v`，得到一个必然不存在的目录。

判据把「显式声明默认值」这种合法写法判成缺陷，属于假红一类。假红比漏报更贵：它教人绕过门——
本仓的处置是删掉这行声明，但那只是躲开判据，不是修判据。

## 修复

`_declared_base()` 在既有分隔之后按中英文分号截断（`tools/lab/doc_chain.py:405` 起），
默认值、`本批次目录` 与相对路径三种写法都回到原有语义；同时新增判别夹具
`python3 tools/lab/doc_chain.py --self-test` 用例 98（同行多字段 + 默认值声明必须通过）。

## 回归检查

- 修复前后对照：修复前该声明形式判红，修复后本批 README 的同类写法不再报 C9 落点基准。
