## 现象

2026-10-23 整门变异实跑（副本内，58 项，评审第一轮补两条后）：**51 杀死、7 存活、0 无效**。七个存活项是同一批老面孔，
每一次复跑都原样存在，但至今没有任何一条被逐项解释过「为什么这条破坏没被门抓住」：

```text
M13 存活   workspace.issues-layout        tests              exit 0
M17 存活   common.files-containment       tests              exit 0
M21 存活   schema.pattern                 tests              exit 0
M24 存活   schema.max-items               tests              exit 0
M25 存活   schema.contains                tests              exit 0
M31 存活   docs.version-prose             tests              exit 0
M36 存活   manifests.name-agree           tests              exit 0
```

存活数从历史口径的 6 涨到 7，不是门变差了：本批把 `schema.contains` 的漂移锚点回填成源码原文
（见 ISS-2026-10-23-变异语料锚点漂移致判据不可观察），这条变异**第一次真正被执行**，于是它长期躲藏的「无效」状态变成了一个可见的
「存活」。这正是为什么「无效」不能当没事——锚点漂移会让一条判据的判别力长期不可观察。

门在这些破坏下仍然返回 0，意味着两种情况之一：判据确实抓不住这种破坏（那要有豁免理由），
或者 `tests` 子项的语料里根本没有能触发它的样例（那是语料缺口）。**从报告上无法区分这两种**，
这本身就是缺陷——「变异存活数 6」这个数字不带可行动信息。

## 根因

2026-10-20 的复核把存活原因写成一句概括（「为语料缺少该违规类实例，非门失效实证」），
写在计划文本里，既没落到 `EXEMPT`（那里只有 `reports.*` 与 `checks.skip-guard` 三条），
也没有为每个存活类补负例语料。概括式结论无法逐项证伪，于是复跑一次就复制一次疑点。

`tools/lab/mutate.py` 的覆盖表只要求「每个 ITEMS 条目至少一个变异或一条 EXEMPT 理由」，
不要求「每个存活项都有归宿」——存活是运行期结果，声明期看不见。

## 备注

修复方向（下一批）：为六个存活类各补一条 `tests` 语料（构造一次违规的临时仓），补不出的写进
`EXEMPT` 并给出为什么不可观察；再把「存活项必须有归宿」做成 `mutate.py` 的报告约束。
本批不承接（范围见 `docs/features/feature-2026-10-22-追溯闭环与证据在场/proposal/proposal.md` §1.3）。

## 修复

为五个当前存活项补判别测试：`workspace.issues-layout`（未知目录拒绝）、`common.files-containment`（绝对路径与越界拒绝）、`schema.max-items`（等值与溢出）、`docs.version-prose`（版本字面量）、`manifests.name-agree`（名称分歧精确断言）；M21/M25 由既有测试杀死。整门 60/60。

## 审查

2026-10-30 独立复核：整门变异 60 项 = 60 杀死 / 0 存活 / 0 无效。原 7 个存活项中 M21（schema.pattern）与 M25（schema.contains）已由既有测试杀死；M13/M17/M24/M31/M36 由新增/收紧的测试杀死（workspace 未知条目、绝对/越界 files、maxItems 等值与溢出、版本散文、manifest 名称精确断言）。证据 `docs/features/feature-2026-10-25-总体评审吸收与修复/testing/agentflow-review/evidence/mutation-final-2026-10-30.txt`。
