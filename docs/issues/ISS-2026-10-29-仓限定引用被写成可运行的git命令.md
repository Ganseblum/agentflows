## 现象

预期：记录给读者的取回命令必须能直接照跑。
实际：删除 L3 批证据件时在批次 README 写的取回方式是
`git show agentflows@6229a65:docs/features/…/evidence/<文件名>`，实测输出逐字为

```
致命错误：无效的对象名 'agentflows@6229a65'。
```

而同一路径去掉仓名后 `git show '6229a65:docs/features/…/evidence/adoption-implementation-map.json'`
正常返回文件内容。影响面：凡是照 `仓库@修订:路径` 形态写「可直接运行的命令」的地方都成立。

## 根因

`error_kind: ai-ignored-doc`。`skills/agentflow/references/document-chain.md` 的门 8 把
`仓库@修订:路径` 定义为**记录侧的仓限定载体**（用途是让没有该仓的读者知道去哪个仓解析，
并在正文内嵌决定性片段），它从来不是 git 语法。本批把它同时当成了「可复制执行的命令」，
两种用途在同一行里被混用——链契约的原文是「跨仓写 `<repo>@<revision>:<path>`」，
未说它可执行，属我方越界使用而非契约缺字。

## 修复方案

- 已采纳：给读者的命令写 git 形态（`git show <修订>:<路径>`），仓限定串只作为**引用载体**出现；
  两者同处一行时写明各自用途（L3 批 README 已照此改）。
- 待审核：是否在链契约的门 8 加一行「仓限定形态不是可执行命令；需要给读者可执行形态时写 `修订:路径`」
  （属受保护面文本，需授权，本批不自行落地）。

## 修复

`docs/features/feature-2026-10-26-L3工作流增强/README.md` 的取回说明改为可运行形态，
并逐字记下本次实测报错原文与本记录路径；本批设计文件的载体表述同步区分「引用形态 / 可执行形态」。

## 回归检查

实跑命令与结果见 `## 现象`（两条同路径、一红一绿即为判定）。
未运行部分：门侧无任何判据能识别「把仓限定串当命令写」，属未覆盖形态，随本轮评审一并上报。

## 怎么避免

引用形态与可执行形态在同一行里各司其职（README 已如此写）；是否升级为链契约条款待用户定，
不写成已落实机制。
