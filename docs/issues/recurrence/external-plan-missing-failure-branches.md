## 类模式

同一份外部计划（infinite-canvas 第六期·AI 办公助理产品线）在 2026-09-19 的一轮评审里，被同一种缺陷
反复命中八次：不是某一节写错，而是**失败分支与安全边界整块不存在**——异常矩阵没有、关键链路时序没有、
发布顺序与回滚没有、可观测性没有、鉴权与产物消毒没有、结算/恢复这类循环与竞态没有定义。

这八条的 `error_kind` 都是 `missing-constraint`（另有八条同批记录分属 logic-error / ai-ignored-doc /
hallucination / other，未并入本类：它们的失败方式不同，混进来只会让类失去判别力）。

## 归纳内容

- **判别方式**：一份计划如果在「风险/对策」「验收标准」之外找不到失败分支的承载面（每条关键路径一张
  异常矩阵；超时、重复请求、状态冲突、回调失败各自有检测方式、处理策略、重试方/次数/退避、幂等前提），
  就属于本类。缺其中一格是本类的一次 occurrence，不是风格问题。
- **吸收点（2026-10-19 条款级核对，已确证）**：
  - `agents/reviewer.md` Design 文档模式的设计完备性条款自 **0.5.1**（提交 `f4c32b8`「0.5.1 文档
    评审模式——吸收 spec/design/proposal 的质量判据」）即在盘，**先于**本类八次命中（均记
    `agentflow_version: 0.8.0`）——八次命中全部是 reviewer 按该条款查出的外部计划缺陷，属**检出**
    而非逃逸；这也回答了台账此前的第一个存疑（「是否因本类而被加进去」）：条款早于本类存在，
    本类不是条款的动因，但条款完整覆盖本类 territory。
  - 安全专项清单（授权与认证态矩阵、密钥处理、注入与输入校验面、产物渲染消毒、租户隔离与限流）
    于 **2026-10-19 补入 `agents/reviewer.md` Design 模式（0.11.0）**，闭合 ISS-015/016 此前仅有
    一般性「安全边界」条款（`skills/agentflow/references/contracts.md`、`roles.md`）的覆盖缺口。
- **条款级对应（八次命中逐条）**：
  - ISS-2026-09-19-office计划缺异常矩阵（缺异常矩阵）→ Design 模式异常矩阵条款（超时 / 重复请求 / 状态冲突 / 回调失败；
    重试格子写明责任方、次数、退避、幂等前提）；
  - ISS-2026-09-19-office计划缺关键路径步骤表（缺关键路径步骤表）→ 以步骤表为基准的关键链路时序条款；
  - ISS-2026-09-19-office计划缺可观测性（缺可观测性）→ 可观测性具名条款（失败如何通过日志、指标、trace 定位）；
  - ISS-2026-09-19-office计划缺发布顺序与回滚（缺发布顺序与回滚）→ 与回滚点配对的发布顺序条款；
  - ISS-2026-09-19-office计划恢复与扩缩竞态（恢复与扩缩竞态）→ 幂等、并发与事务边界说明条款；
  - ISS-2026-09-19-office计划结算循环未定义（结算循环未定义）→ 异常矩阵的状态冲突 / 回调失败格（部分对应：结算循环不点名，
    靠评审推演暴露）；
  - ISS-2026-09-19-office计划无鉴权rce原语（无鉴权 rce 原语）/ ISS-2026-09-19-office计划产物渲染缺消毒（产物渲染缺消毒）→ 安全专项清单（0.11.0 新增）。
- **档位**：八次命中版本均为 0.8.0，早于 `consolidated_in` 0.11.0 → `recurred`（类出现过多次，
  吸收于 0.11.0 完成）；此后再出现命中将判 `escalated`。
- **为什么保留十六份记录而不删除**：这十六条被根评审记录 `reviews/infinite-canvas-office-agent-plan/review-2026-09-19-001.md`
  的 `findings` 逐条点名；删掉会让 findings→bug_id 的交叉核对变红，而要改那条记录就得动一个被声明为
  不可改写的评审记录。聚合到本台账已经达到「吸收」的目的：一个类 + 八次 occurrence，可查询、可计数。
  十六条记录保持 `open`——它们是对外部计划的有效发现，infinite-canvas 仓不在本机、本仓无法代为修复；
  本仓侧的收敛即本台账的归纳（条款级对应如上）。
