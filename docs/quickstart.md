# 五分钟开始一次交付

先把用户结果、禁止事项和检查方式说清楚，再让 AI 在已授权范围内连续执行。模型、工具和权限由宿主管理，Agentflow 提供方法、角色与证据约定。

## 选择路径

| 当前任务 | 从哪里开始 |
| --- | --- |
| 纯问答或只读了解 | 直接调查，不建立实施链或空记录 |
| 行为变更或缺陷修复 | [执行与验证](../skills/agentflow/references/execution.md)：目标测试先有效失败，再实现与回归 |
| 简单明确且无高风险边界 | 按[六条轻量判据](../skills/agentflow/references/document-chain.md#文档档位)使用单份 feature README |
| 跨层、公开契约、数据、权限、共享时序或难回退 | 完整文档链，先做架构判断 |
| 用户明确要求整套文档 | 完整链；不以任务简单为由减少所需交付物 |
| 遗留测试缺口 | 测试链盘点模式；不把补测授权扩大为生产修复 |

判断词只有一处定义：[小改动与 risky work](../skills/agentflow/SKILL.md#判断词的可判定定义)。角色按需要选，查[角色路由](../skills/agentflow/references/roles.md)，不必先记完整名单。

## 第一次接入项目

复用已有 AGENTS.md 和项目文档位置；只有缺失项需要确认。检查命令必须有仓库依据并实际核验，不猜值。按 Skill 的 [Init](../skills/agentflow/SKILL.md#首次接入init) 写一次项目约定，以后沿用。跨仓全局规则是另外一次[宿主接入](../skills/agentflow/references/hosts.md)，不由项目初始化顺带写入。

## 六组短提示词

下面是入口示例，实际工作继续遵守项目规则和已授权范围。

### 1. 查现状

```text
先查这个需求已有的能力、真实契约和可复用代码，指出尚未闭合的路径。
每条结论附文件与行号；区分可查事实和需要我决定的行为，暂不写实现。
```

### 2. 澄清

```text
只问会影响行为、权限、兼容或验收的未决问题，先解决前置项，给推荐与理由。
已答内容继续使用，待定项原样保留，不替我补产品决定。
```

### 3. 整理规格

```text
把确认内容写回现有需求真源：目标、非目标、正常路径、禁止事项、失败恢复和验收。
按风险选择轻量或完整材料，不复制另一份需求正文。
```

### 4. 制定计划

```text
按用户行为切片列步骤、真实依赖、测试入口、环境与回退方式。
每个切片先有效失败、再最小实现和相关回归，完整验收清单不能漏掉。
```

### 5. 连续执行

```text
在已授权范围内按计划连续完成，不逐步等待“继续”。
及时回写已接受任务的状态与原始证据；触及停止条件再升级，不删测试制造绿色。
```

### 6. 核验交付

```text
分别核对记录合法、目标用例实际满足预期、需求与断言覆盖经过独立复核。
给最终输入、精确用例和原始输出，列出失败、未验证、阻塞及下一动作。
```

## 收尾

作者不能批准自己的实现；摘要不是证据。行为与回归实际通过后再独立评审，未运行项不算通过。必要时用 `workflow.py` 绑定计划、快照和原生报告，说明 JSON 仅作已有记录的证据。

在本仓接受产物前跑 `python3 tools/lab/validate.py all`；文档链完成前跑 `python3 tools/lab/doc_chain.py <feature-dir>`。目标仓使用自己的检查命令，跨仓文档检查从插件根调用并带 `--root <目标仓根>`，不能将插件仓的检查范围套到业务项目。
