- 所属阶段：`proposal`
- 目标阶段：`proposal -> spec -> design -> plan`

## 一、背景与目标

### 1.1 背景

编码宿主（Codex、Claude Code、ZCode）已经把模型、登录、工具、权限、终端体验和 Agent
生命周期做成熟，但**多角色协作的工程纪律**没有宿主愿意内建：谁负责什么、改动怎么验收、
证据怎么落盘、工具改自己时怎么防止改坏评分规则——这些在每个业务仓里被反复重新发明，
质量取决于当次会话的自觉。

Agentflow 最初的形态是散装 Skill 与角色说明，随着真实任务（业务仓功能开发、bug 链路、
外部文档评审）与自迭代审计的推进，暴露出三类问题：能力声明了但没有执法面（0.3.x 时代）、
方法改动没有业务尺子（0.6.0 前）、产品演进没有结构化文档链（0.8.x 后仍在以对话与散装
决策记录承载产品结论）。

### 1.2 目标

- 把协作方法做成**可移植的宿主插件产品**：用户留在成熟宿主里，Agentflow 只定义如何组织工作。
- 让方法自身的演进可治理：证据 → 假设 → 候选 → 独立评测 → 人批门，工具改自己时不能改评分规则。
- 让产品的每一步演进有四层文档承载（proposal → spec → design → plan），机器校验 + 独立评审。

### 1.3 本期范围

本期包含：

- **架构拍板**：做产品不做运行时；方法通用、测量按宿主发证书（已拍板，见第四节）。
- **第一次 improve 闭环**：公开用例噪声底仪器，跑出 first better/neutral/worse（live 对照进行中）。
- **打包分发**：瘦快照 runtime（运行时面与实验室控制面分开），marketplace 源指向生成树（已落地）。
- **宿主认证矩阵**：方法写一次，测量证书按宿主逐个发（Claude 先、ZCode 次、Codex 基线证）。
- **业务尺子**：`evals/business` smoke 对照，让方法级改动从 `measurement: none` 走向可度量。
- **产品文档链**：本目录的 proposal/spec/design/plan 四层（本提案即其产物）。

本期不包含：

- 自建运行时、Provider、TUI、可视化 Flow 编排（明确不做，见第六节）。
- 自动灰度、自动 promote（人批门是原则，不是暂时做不到）。
- 向量检索 / RAG 语料化原始对话（记录量不够，检索先 FTS5）。
- 私有 holdout 服务与跨机器评测分发。

## 二、产品定位与核心原则

本产品是**宿主原生的多角色协作方法**，不是框架、不是平台。核心原则：

1. **宿主是运行时**：模型、登录、工具、权限全部用宿主的；Agentflow 只提供组织方法。
   不 invoke 独立 CLI、不要求 Agentflow API key、不要求 Agentflow MCP server。
2. **角色是能力不是流水线**：14 个角色是按需取用的能力清单，默认路径短；完整角色表是进阶。
3. **治理优先**：自迭代是受治理的版本发布系统，不是"Agent 觉得哪里不好就改自己并上线"。
   独立评测、预声明拒绝条件、不可变版本、人批门，一个都不能少。
4. **作者不自证**：产生改动的角色永不验收自己的改动；supervisor 自己写的部分，独立评审门
   不可豁免。
5. **证据编译**：任何"做完了"的声明必须映射到一个可复现的检查；不可复现的检查视同没跑。
6. **诚实声明**：做不到、未验证、角色分离而非环境隔离——如实写进文档与记录，不粉饰。

## 三、用户与场景

| 用户 | 场景 | 承诺 |
| --- | --- | --- |
| 业务仓开发者 | 跨层功能、高风险 bug、需要评审门的改动 | 委派 + 独立评审 + 证据落盘的完整链路 |
| 业务仓负责人 | 给外部系统产出的 spec/design 做第二道评审 | 评审桥：快照评审 + bug 记录归因 |
| Agentflow 维护者（用户本人） | 方法演进与自迭代 | 改进环 + 人批门 + 保护门 |
| 新会话（无上下文） | 接手任意一条线继续工作 | 记录体系可检索，计划即看板 |

OQ-1（待冻结）：业务仓开发者场景缺量化口径——"完整链路"的验收是 validate 九项绿 +
评审记录存在，但**用户侧收益**（返工率、缺陷逃逸率）没有基线。登记进 spec §0，暂不阻塞。

## 六、明确不做

- 运行时 / Provider / TUI / 可视化 Flow / 组织图产品化（LangGraph、CrewAI、Dify 管循环，
  本产品管协作纪律、证据编译、改自己时不能改评分规则）。
- 自动灰度与自动 promote。
- 原始对话进 RAG 语料；检索面只做记录库（FTS5）。
- 绑死单一宿主。
